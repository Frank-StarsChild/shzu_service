# 接口与数据对象说明（对齐方案第 6.3 / 11 节）

## 1. 数据对象

| 对象 | 存储位置 | 核心字段 |
|---|---|---|
| Document | `data/reviewed/documents.json` | doc_id, title, issuer, source_url, published_at, document_year, effective_from/to, review_state, notes |
| Clause | `data/reviewed/clauses_*.json` | clause_id, doc_id, exact_text, topic, student_type, application_year, source_locator, scope_status, time_condition |
| Fact | 同上 | fact_id, subject, predicate, value, unit, conditions, evidence_ids, topic, label |
| Rule | `data/workflows/rules.json` | rule_id, flow_id, required_fact, operator, expected_value, exception_conditions, evidence_ids |
| FlowSpec | `data/workflows/flows.json` | flow_id, version, applicable_scope, steps, required_slots, rule_ids, materials, timeline, template_id |
| TaskState | `data/app.sqlite3` tasks 表 | task_id, session_id, flow_id, revision, slots, rule_results, current_step, kb_version |
| Artifact | `data/app.sqlite3` artifacts 表 + `data/artifacts/` | artifact_id, task_id, task_revision, template_version, format, path, evidence_manifest, expires_at |

`effective_to` 等未知字段保持空值；未审定 `scope_status` 不得自动扩大为全校适用；
PDF 定位用物理页序、HTML 定位用段落/表格行；模型不推测页码。

## 2. 检索链路（backend/app/knowledge）

```text
问题规范化（别名归一）
  → 年度缺口 / 时间条件检查
  → 强办理意图（进入向导）
  → qa_topics 触发词（最长命中优先）
  → BM25 检索（jieba 分词，域内泛词剔除）
  → RRF 融合（事实/条款两路）
  → 范围与时间检查
  → 事实卡 + 原文摘录 + 下一步
```

阈值：`config.RETRIEVE_SCORE_MIN = 2.2`（开发样本校准，见 `scripts/smoke_test.py` 与评测报告）。

## 3. 会话与任务

- `POST /api/v1/chat` 不强制登录；服务端按 session_id 记录最近查询；
- 向导任务在对话中创建（`status=wizard`，返回 `task`），也可 `POST /api/v1/tasks` 直接创建；
- `PATCH` 更新槽位 → 重新计算规则 → revision+1；前端 450ms 防抖自动保存；
- `POST /exports` 校验 `task.kb_version == kb.kb_version`，一致才渲染；
- 草稿删除：`DELETE /api/v1/tasks/{id}`（个人草稿删除入口，对齐方案第 14 节）。

## 4. 版本

- 知识版本：`documents.json.kb_version`（当前 `kb-2026-11-18-r1`）；
- 模板版本：`renderer.TEMPLATES`（如 `2025-附件2-结构版`、`skxy-v1`、`jwc-v1`）；
- 产物记录 `task_revision + template_version + evidence_manifest`，用于导出核对与追溯。
