首页问话入口恢复实施提示词

请你在这个仓库里直接修「石大智多星」首页。我要解决的是底部那个「想办什么事？」输入框和右边的「问」，以及它在观景时没入口的问题。右侧显示回答的面板是另一回事。改完后，请在浏览器里从首页亲手问一次问题，把你实际测到的情况告诉我。

一、先复现，再改代码

1. 在 `frontend` 目录启动现有 Vite 开发服务。桌面上用 1440×900 的视口打开 `/?3d=1&intro=0`。先确认上面是石大智多星、下面是 3D 沙盘，底部能看到输入框。也可以用 `/stage?3d=1&intro=0` 直接进舞台。`intro=0` 只是为了本次测试跳过开场。
2. 在底部打「学生证丢了去哪补办」，先别发送。点「观景」，等淡出结束。当前代码里输入框其实还在 DOM，隐藏它的是 `.stage.is-tour:not(.is-idle-tour) .stage-dock`。它让整条问话栏 `opacity: 0`、`pointer-events: none`。当前右上角有「退出观景」，按 Esc 也会恢复，草稿还在。还有一个已复现的问题，观景时按 Tab，焦点可以进已经看不见的示例问题、输入框和发送按钮。
3. 再打开 `/stage?3d=1&intro=0&idle=2`。这里的 `idle=2` 是把自动转动等候设成两秒，方便验证。聚焦输入框后停一会儿，当前仍会进入空闲自动转动，问话栏却保持可见且可点。这两种观景都使用 `mode === 'tour'`，用 `idleTour` 区分。普通首页和测试过的静态舞台也能看到输入框。如果你在别的状态看到输入框消失，记下 URL、视口、主题和操作，先确认是元素没挂载、被隐藏、跑出屏幕，还是被别的面板盖住。
4. `/` 是 `EntryView.vue` 的入口。宽度小于 1100 CSS 像素或 3D 能力判定为静态时，可能进入普通版 `HomeView.vue`。普通版的 `.composer` 在页面首屏内容里，提交走现有的 `/chat` 流程。只有实际进入舞台时才找 `[data-testid="stage-dock"]`；舞台的提问走 `useChatStore().send()`，结果就在当前地图旁边打开。

二、我要看到的效果

默认首页、选择校区、定位楼栋、展开或收起回答、回答请求进行中，以及沙盘加载或显示静态海报时，都让完整的「输入框＋问」留在底部原来的位置。用户可以接着写下一句。请求进行中按现有 `busy` 规则拦住重复提交。

我自己点「观景」时，地图可以继续缓慢转动，整条问话栏照原来淡出。屏幕底部留一枚清楚的「问智多星」按钮，右上角仍可点「退出观景」。点「问智多星」后，退出观景，恢复进入观景前所在的首页、校区或回答状态，同时把光标放回原来的输入框。刚写了一半的问题还在，由我自己按「问」发出去。点右上角退出或按 Esc 同样能回到原界面，焦点回「观景」按钮。首次加载页面时沿用页面正常焦点顺序。

自动空闲转动时，完整问话栏一直在。光标已经在输入框里，就暂停空闲计时；点到别处后再开始计时。已经自动转起来时，点输入框或用键盘进入输入框，恢复原来的输入状态，当前这次点击或按键照常生效。输入法选词时按 Enter，先让输入法上屏，用户再次按 Enter 后才发问。减少动态模式继续走项目现有规则。

二十四院罗盘打开时，允许它的遮罩暂时盖住地图和问话栏。用现有的收起按钮或 Esc 关掉后，原来的问话栏要马上可点，输入中留下的内容还在。

三、按这个顺序改

1. 先改 `frontend/src/views/StageView.vue`。这里已经挂了 `<AskDock />`，旁边有「退出观景」按钮。用 `store.mode === 'tour' && !store.idleTour` 得出是否为手动观景，让同一个判断控制右上角退出和新增的底部「问智多星」。新增按钮和 `<AskDock />` 放在同一层，按钮可以用 `data-testid="stage-tour-ask"`。这样原来的问话栏淡出时，这枚按钮仍在，也有自己的点击范围。用普通 `button`，`type="button"`。打开地图、切换校区时页面上只有一套实际的提问表单。
2. 在 `frontend/src/components/stage/AskDock.vue` 里给输入框加模板 ref，通过 `defineExpose` 暴露一个聚焦方法。需要恢复「观景」按钮焦点时也可用同样方式。点击「问智多星」时复用 `store.setTour(false)`，等 `nextTick()` 后聚焦输入框。可以用 `focus({ preventScroll: true })`，不要因为这一点让整页跳动。右上角按钮和 Esc 共用退出观景的逻辑，并在视图更新后把焦点交还给「观景」。保留现有 `AskDock` 实例，草稿 `text` 就能跨观景来回留住。切换时，聊天历史和当前地图状态由现有 store 管理。
3. 手动观景时把 `AskDock` 根元素设成 `inert`，同时保留 `.stage-dock` 的淡出样式。进入手动观景后，把焦点挪到画面上可见的「退出观景」按钮；随后能通过 Tab 到「问智多星」。退出时先恢复问话栏可交互，再做聚焦。CSS 的 `pointer-events: none` 只管指针，单靠它拦不住 Tab。检查 `inert` 在退出时确实被移除，空闲自动转动时也不带这个属性。
4. 在输入框的 `focus` / `blur` 上报输入焦点给 `StageView`。把焦点状态加进 `canIdle()` 和重新计时的监听。获得焦点时取消已安排的空闲计时，若已经处在空闲自动转动里，就走现有 `exitIdleTour()`。失去焦点后调用现有 `armIdle()` 从头计时。记得保留已有的 pending、罗盘、减少动态等判断，以及卸载时清理定时器和事件监听。需要补输入法保护时，直接复用 `AskDock.vue` 现有的 `composing` 和 composition 事件，在表单提交入口守住这段交互。现有的「你说的可能是」地点预判和示例问题继续使用现有逻辑。
5. 再收一下视觉。默认状态保留暖纸色或深墨色的输入底板、朱砂色「问」按钮和底部居中的布局。给输入框补上可读的无障碍名称，例如 `aria-label="向智多星提问"`。通过 `:focus-within` 给表单外框加一圈清晰的焦点提示，同时保证键盘用户能区分焦点是在输入框还是「问」按钮上。手动观景的「问智多星」可以用同一套朱砂底和浅色字，手机上按钮高度至少留 44 CSS 像素。新按钮用 `.stage` 范围内的样式，底部优先复用 `--st-dock-bottom` 和现有安全边距，给手机安全区留空间。右上「退出观景」复用已有样式。
6. 默认布局参考 `frontend/src/styles/stage.css` 的底部三区，以及 `AskDock.vue` 的对应样式。遇到短窗或放大后，优先把示例问题和状态工具压紧，让实际表单、发送按钮、错误/取消等当前操作仍能使用；地图署名要保留且可读。检查罗盘、比例尺、右下读数、署名和右侧回答面板在关键尺寸下都没压上表单。遇到真实遮挡就修改对应的宽度、边距或排布，复用已有层级关系。若新加的入口实测会被地图标签压住，先看 `frontend/src/stage/labelBoard.ts` 已有的 `.stage-dock` 避让机制，再按同样方式登记入口占用范围。用 DevTools 看计算样式和 `elementFromPoint()`，别只靠把 `z-index` 改得很大。

四、改完按下面验收

1. 桌面 1440×900 和 1366×768，日间和夜间都试。刚打开就能看清、点到输入框和「问」。切换校区，问「学生证丢了去哪补办」，看到地图页面内的回答后再发一条。收起、展开回答各试一次。点发送和按 Enter 各验证一次。接口返回慢时试一次重复提交，应该只发一轮。
2. 手动观景用刚才的草稿重测。点「观景」后底部有「问智多星」、右上有「退出观景」，Tab 不会去透明的输入框。点新按钮后输入框拿到焦点，内容和校区选择正确，也没有自动发送。再分别用右上按钮、Esc 测退出，确认焦点回到「观景」。用 `getComputedStyle(dock).opacity` 验证淡出和恢复，用 `toBeFocused()` 验证焦点。Playwright 的 `toBeVisible()` 单独使用会把透明但仍有布局框的元素算成可见。
3. 用 `idle=2` 验证空闲转动。输入框聚焦超过两秒时不触发；点到沙盘上并停止操作后能转；转动时原输入框依然可填可提交。用中文输入法试一遍候选上屏和真正提交。再检查开关二十四院罗盘后问话栏恢复可点。
4. 用 390×844 打开 `/`，确认普通版原有输入表单能提问；再用 `/stage?3d=0` 测静态舞台。单独模拟模型或接口请求失败，确认舞台的输入框依然显示。用 Playwright 拦模型时，按 `url.pathname.endsWith('.glb')` 匹配，模型请求带版本参数。看到「3D 加载失败，已显示静态图」后，再尝试点击、输入。用一个短窗或 125% 浏览器缩放检查底部没有重叠；若有真机，再用软键盘核对输入框和发送按钮都能使用。手动实测和 Playwright 测试是不同验证，最后分别写清结果。
5. 在 `frontend` 下运行 `npm run build`。修改手动观景的回归用例优先在 `frontend/tests/e2e/stage-orbit.spec.ts`，空闲行为参考 `stage-impact.spec.ts`，发问参考 `stage-ask.spec.ts`，输入预判参考 `stage-mention.spec.ts`，首页分流参考 `stage-entry.spec.ts`。跑相关用例即可，注意一些既有用例会更新仓库截图，可以用 `--grep` 先挑实际涉及的用例。例如 `npx playwright test tests/e2e/stage-orbit.spec.ts --grep "点观景|退出观景"`，具体按当时的测试名调整。用现有 API 模拟来验证前端交互；有后台时，再做一次真实提问。出现失败就写明具体是哪一条和复现方法。
