给执行模型的话

我想给「石大智多星」加一个能接住问答结果的办事工作台。请直接在当前 Vue 3 项目里做。我希望看见的效果是这样的：学生在沙盘上问哪里补办学生证，回答回来，面板顶部立即出现「去哪」「出发前确认」以及一个能点的定位入口。学生看原文回来，还是刚才这件事。换成问奖学金，那个位置就变成材料和年度核对。学生今天先填一半，下一次打开服务目录能看到自己停在哪一步。

仓库里已经有沙盘的另一套施工方案。请先看 docs/3d/ALIVE.md 的「任务卡」和相关章节。院徽、二十四院罗盘、输入地名预判、分段作答和检索动效都有自己的任务卡。这一轮做问答结果、证据核对和继续办事这几件事，接已有能力。先看 git status。当前工作区可能有其他人在改的文件，请保留那些内容。使用仓库现成的 Vue、TypeScript、Pinia、路由和样式。

一次只做下面一张卡。默认这一轮做第 1 张。如果我明确说了卡号，就做那一张，先确认它依赖的卡是否已完成。做完后告诉我实际看到的效果和验收结果。每张卡都可以单独发给新会话。接着做后面的卡时，以代码里的现有实现为准。

第 1 张：让回答一出来就能操作

先读 frontend/src/api/client.ts、views/ChatView.vue、components/stage/AnswerPanel.vue、components/ActionCards.vue 和 stores/chat.ts。当前回复的真实信息在 ChatResponse 里。最常用的是 status、actions、clarify、workflow、answer、citations。聊天和沙盘现在各自有一部分展示判断。请先写一个很小的纯函数，给它当前这条助手回复，它返回这一轮最该展示的动作。简单的类型联合就够了。接两个现有界面，按钮还走它们已有的事件和 store。主动作最多一个。

按这个顺序来。
1. 当前轮需要追问时，展示 clarify.question 和 choices。文本显示 label，点选提交原始 ID，调用现有 pickChoice。只让仍在等待回答的最新追问可点。文本补充复用原有输入框。点击和网络忙碌状态使用现有防重复提交、取消、重试逻辑。
2. 有 errand 办事单时，顶上显示「楼名 + 房间号」，旁边留能用的定位动作。下面放一到两条出发前提醒，完整事项仍能展开看。地点取 place，部门取 dept，时间取 hours。缺办公时间就显示「办公时间待确认」。调用定位时使用有效 building_id。对同一楼栋关联的 errand 和 place，保留一个主按钮。多候选地点用列表，让学生自己选。请检查 stage/places.ts 和 StageView 现有的自动定位衔接，确认歧义时没有提前飞到第一项。
3. 有 repair 报修卡时，先显示已识别的校区、楼栋、影响范围和第一条已有自查步骤。更多步骤能展开。草稿有内容才显示「复制报修草稿」，使用原复制逻辑并保留「未提交」状态。公告未找到、官网访问失败和覆盖当前地点的公告，按接口实际状态展示。
4. 有 checklist 时，顶部显示真实的核对项数和需要用户补充的项数。可以折叠分组，点开还是原来的材料行和出处。四种状态读接口里的 verified、needs_user、needs_college、needs_web。「已有依据」表示校规或材料已有来源。学生有没有备齐材料、能不能通过审核，由各自真实的状态决定。有 flow 才显示进入向导的入口，使用真实 flow_id 和现有预设传递方法。historical 为 true 时，把「历史演示」放在按钮旁。
5. 仅有 workflow 时用现有向导入口。没有任务类字段时，保留原来的正文和引用。旧响应缺 actions 也照常显示。等待、取消、超时沿用现有状态。接口整包返回时，等待文案用「正在查询校内资料…」。如果已有真实流式事件，按既有事件更新显示。普通聊天不必增加额外的信息块。

操作卡可先用简短标题和一行摘要。放在这一轮回答的开头。桌面留足正文行宽。沙盘只放进已有右侧面板，可折叠，保持画布仍可操作。手机单列，主按钮至少有 44 像素的可点高度。可以先复用已有卡片的内部组件，再提炼确实重复的逻辑。改变顺序后，引用仍应属于原消息。

验收。用「学生证丢了去哪补办」「宿舍网断了怎么办」「今年国家励志奖学金怎么申请」「你好」走一遍。验证两端用同一个接口响应会给出同类动作，一条普通问答里不会凭空出现办事卡。再用一个多候选地点响应，点第二个选项，应定位到第二个楼。有楼名而没有楼号时，应保留文字。在测试里故意把现场办事单和地点卡的楼号设成同一个，主定位动作仍应只有一个。

第 2 张：让人能核对这一条依据

先读 components/EvidencePanel.vue、AnswerBlocks.vue、views/SourceView.vue 和 stores/source.ts。现有页面已经有引用面板和出处页。现在把「哪句话对应哪条依据」做得更容易看。一条证据入口应随正文中对应的 citation_ids、材料项中的 evidence_ids，或办事地点中的 evidence_id 出现。当前轮的 citations 作为编号和内容来源。收到找不到对应引用的 ID 时，原文仍能读，页面不生成一个看似可点击的空编号。

电脑点一次引用，侧边直接见到文件标题、发布单位、发布日期或适用条件、摘录。手机优先在当前回答附近展开，下面仍可继续看正文。支持继续打开已有来源详情。详情请求失败时先用回答自带摘录。快速点 A 再点 B，旧请求后来完成时，当前界面仍是 B 的内容。实现时把选择与本轮 request_id、引用 ID 一起绑定，已有 source store 可复用。

加一个「对照出处」轻量入口。只有当前条内容关联两条及以上不同出处，而且标题、公告日期或适用条件确实有差异时出现。第一版支持选两条同看。并排或上下显示标题、发布方、时间条件和本条摘录，每列保留自己的原文入口。只显示有明确值的日期，日期缺失可以标「未标注日期」。例如一份材料清单引用了上一年度通知和另一个规章，把两条的适用范围摆出来。现行结论沿用后端已有判定。

验收。准备一条两出处的材料项和一条单出处的地点。前者能并排对照，后者只打开单条。模拟一次详情加载失败、一次快速切换引用和一次手机宽度。历史回答的证据选择只作用于被点开的那一轮。

第 3 张：办事台记住可以继续的那一步

先读 views/HomeView.vue 的「继续办理」、views/ServicesView.vue、stores/flowDraft.ts 和 views/WorkflowView.vue。首页已经能读到草稿。把它整理成可复用的「继续办理」小区块，先接服务目录，再接沙盘的非观景状态。使用 listDrafts()。第一屏最多显示两条，按 updatedAt 排序，每条只显示事项名称、上次的步骤和下一项待填标签。没有下一项的，按钮叫「查看上次进度」。没有合适草稿就不额外占用首屏空间。点卡继续用 /workflows/:flowId?draft=<会话标识>。不要往卡片里放表单的实际姓名、电话、住址、排名或原聊天文本。个人字段仍由原向导负责。

服务目录可以接一个窄小的「常用」区。收藏用明确的图标和「收藏」「取消收藏」操作。目录中的 service_id 是收藏主键，条目名和向导入口仍取 api.services() 的当前数据。存储只放用户主动收藏的 ID。收藏后保留目前的筛选词和滚动位置。某个收藏服务已经不存在时，展示「该服务暂不可用」并提供移除。重新进入页面时，仍能看见之前主动收藏的服务。

在办事向导顶部显示一条现有状态摘要。用 workflow store 和 PreviewResponse 的真实字段展示「当前第几步」「哪一项待填」「预览需重新核对」。点击待填项时，如果它在当前步骤就跳到表单字段，已有跨步方法时再跨步定位。改字段后仍由现有逻辑使旧预览失效。文书下载发生后只能说明文件已导出。材料核对和导出使用已有接口。

验收。写一个草稿，离开向导，从服务目录点回来，步骤和已确认的内容准确恢复。修改表单后要重新核对才可导出。收藏后刷新仍能找到同一服务，删除收藏后刷新看不到。清空本地存储或浏览器存储不可用时，原来的服务目录和直接进入向导仍可使用。

第 4 张：出门前带走一张办事摘要

先在 errand 上做一个「复制出发前清单」。先预览学生将复制的文本，再点复制。内容来自当前轮的结构化数据，顺序是办什么、去哪里、需确认什么、从哪里查正式说明。地点取已返回的楼名、房间。电话仅使用办事单已有的官方窗口字段，时间取接口明确给出的 hours。材料未确认时只写「出发前向办公室确认材料」。出处使用本轮已有的来源标题和链接。摘要里默认只取这些明确的字段。原问题、用户输入的预设、向导表单、历史消息和姓名、住址等个人字段不放进去。

同一轮有不同地点候选时，先让学生选择，摘要只带所选地点。静态沙盘和手机上也能打开。可以用 navigator.clipboard，把复制成功、复制失败分开提示。失败时保留可选择的纯文本。研究型问答、资料不足和普通闲聊用已有答复方式，不出现空的复制入口。报修继续用现成的「复制报修草稿」入口。

验收。用学生证办事单检查复制结果，确保与界面看到的地点、联系信息、待确认事项和引用一致。把接口里的办公时间删掉，应显示「办公时间待确认」。确认没有把聊天中自述的个人字段复制进去。

统一的视觉处理

沿用 styles/theme.css、swiss.css、stage.css 的现有令牌。日间用暖纸白，夜间用墨蓝，朱砂给当前轮最重要的按钮，金线给引用和分隔。重点看「下一步」「还缺什么」「哪条是依据」。信息密度用大小字号和留白调节，标题、状态、关键词有明确层次。卡自身不盖住沙盘栋楼的焦点。手机上的出处和办事摘要优先在对应内容附近打开。弹层支持关闭、键盘焦点可见，开合有 aria-expanded。只在卡片出现、选中或折叠时做短过渡，减少动态模式下立即完成。院徽使用已有 emblems.json 和相关组件，等资产组件就绪后接入现有学院入口即可。

验收用 1440 和 390 像素两种宽度，日夜主题各看一遍。至少检查一遍键盘操作、很长的学院名、长摘录、空字段、历史数据、页面切换、重复点击和接口失败。手机首屏优先放当前主动作，输入栏打开时仍能滚到卡片末尾。保留当前方案的滚动、沙盘模式选择和 WebGL 降级。

从 frontend 目录跑 npm run build、npm run test:unit 和 npm run check:bundle。端到端复用现有 Playwright 及 tests/e2e/fixtures/api.ts。优先跑和本卡有关的用例，另外确认 flow-guide、stage-ask、stage-place 的原行为。先记录能在当前代码上复现的既有问题，区分本卡引入的问题。最后告诉我做完哪张卡、用户怎么操作、改了哪些文件、真实跑过哪些命令、有哪些结果还没验证。截图和模拟数据要写明来源。
