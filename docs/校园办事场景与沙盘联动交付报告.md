## 一、交付的三个能力

1. **场景一：奖助学金申请核对**——从「今年国家励志奖学金怎么申请」等问法进入。后端工具
   `check_award_readiness` 按知识库依据包生成核对清单，每项标注四种状态：
   已有依据（6000 元/年、资格条件、双排名）、待您补充（年级/认定/排名）、
   待学院确认（学院收件截止日）、待官网核实（2026 年度通知未入库）。
   清单附带官方入口（学生资助管理中心 0993-2057301，带证据）与 2025 年度历史演示向导入口。
   正文由 DeepSeek 按工具返回的真实状态撰写，年度区分如实（2026 缺项明写「未核实，不臆测」）。
2. **场景二：宿舍网络报修分诊**——从「中区 18 号楼宿舍网络无法连接」等问法进入。后端工具
   `triage_network_issue`：识别校区/楼栋（18 号楼→中沙盘 ZQ-B029 18号学生公寓）/设备范围；
   先查本地故障公告、再联网核对网络与信息中心官网首页（首页线索明确标注「标题线索，正文未核验」；
   访问失败如实报告「未能联网核对，这不代表该区域没有故障」）；按官方指南（宿舍网线/拨号错误/
   修复工具页面）输出自查步骤（每步带证据）；交付官方报修入口（用户室 0993-2057898/2057899，
   办公地点证据可查）与可直接复制的报修草稿。**无校方授权的在线提单接口，不真实提交**，
   草稿标注「未提交到任何系统」。
3. **聊天→3D 沙盘联动**——回答附「在沙盘查看」按钮（后端 `locate_campus_place` 按
   campus.meta.json 将地点映射为 buildingId；别名表含 45 栋登记建筑 + N号楼公寓名式）。
   点击打开首页沙盘 `/?focus=buildingId`：3D 就绪时镜头动画停靠到建筑并红色高亮
   （`__campus3d.focusedBuilding` 可验证）；静态降级（?3d=0/小视口/无 WebGL）时保留文字定位。
   未登记楼栋（如东区 5 号楼）只给文字定位并说明沙盘覆盖范围；重名地点（科技一条街东/
   西段）列为歧义候选；**不展示路线长度/步行时间/楼层入口**（无依据数据）。

参考项目落点：campus-rag-assistant 的「转办入口 + 待确认草稿 + 步骤状态可见」体现在
分诊卡与报修草稿（未采用其 GitHub Issues 提单，入口全部来自本校官方资料）；
university-chatbot 的「闭域引用+低置信如实拒绝」沿用本项目审定证据机制。
