## 五、检索改造

- 顺序修正：原「全校 Top K → 学院过滤」改为「先确定范围（学院/学年）再在范围内召回」。
  范围元数据构建时做学院名归一（「信息科学与技术学院（网络空间安全学院）」→ 官方名），
  修复了原实现下信科院 scope 空集的问题。
- 别名与上下文解析保留：colleges.json 别名 + aliases.json 归一 + 歧义校验提示注入模型；
  学院简介意图下概况主题置顶（防止教师档案高频词挤掉简介条款）。
- jieba 专有词表扩充 + 高词频（修复「迎新报到」被切成「迎/新报/到」）。
- 分词结果磁盘缓存：万级条款建索引 51s → 命中缓存 1.8s；FastAPI 启动暖机。

**BM25 基线评测（22 题集）**：hit@6 = 22/22（100%）；跨学院误召回 = 0；单次检索平均
延迟 ~66ms（含分词与 RRF 融合）。覆盖精确查询（姓名「孙桂香/王立昌」职称、文号
「财教〔2021〕310号」、表格名「2026-2027校历」）。

**向量对照（BAAI/bge-small-zh-v1.5 + RRF 融合，可选通道，实测）**：索引已构建完成——
24830 条 × 512 维，CPU 编码 1519s，vector_index.npz 51MB。三通道 22 题集实测：
BM25 基线 22/22（100%）、误召回 0、76ms/查询；**BM25+向量融合 22/22（100%）、
误召回 0、155ms/查询**（每查多一次向量编码约 +80ms）；纯向量单通道 21/22
（未命中「介绍一下生命科学学院」）、跨学院误召回 9 条（向量按语义匹配不带范围
约束，学院限定检索本就不走该通道，属设计使然）。结论：当前题集 BM25 已满分，向量
融合不增命中、稳态延迟约翻倍（~155ms/查，仍远低于 4s 单轮预算）；语义改写/
口语化提问属 BM25 潜在失手场景（题集未覆盖），修复后通道默认生效（SHZU_VECTOR
=auto；置 off/0 可退回纯 BM25 ~76ms）。通道懒加载：首次全校检索时载入模型约 6s
（首查含加载约 20s），之后单查约 200ms；加载失败自动退回纯 BM25，关键词检索
不受影响。启动暖机仅覆盖 BM25 索引，向量模型首次使用时才载入。

## 六、官网补查工具（lookup_official_web）

- 触发：由对话图模型自主决定（本地检索不足/资料过期/问最新情况/缺年份时）。
- 来源发现：优先从知识库登记的学校/学院/部门官网 URL 按板块与学院匹配；
  搜索服务预留 SHZU_WEB_SEARCH_API 接口（当前未配置，未走外部搜索）。
- 隐私：sanitize_query_for_web 剥除长数字串（学号/电话）与身份字段后才出本地。
- 实测：图书馆借阅规定页成功取到正文（web-444396eb91 等）；skxy 站取到会议室
  预约流程正文；chaoxing/jwc 等超时或 ConnectError 的站点如实记入 failures，
  状态文案如实说明「未能取到正文，不得声称已查证」。
- 引用：web-<sha> 证据 ID 注册进当轮 citations，/api/v1/evidence/{web-id} 可打开
  实际官网原文（EvidenceResponse 走 web_evidence fallback）。实测学生证补办一轮
  返回了 web-0391e6fe68 引用并可在前端引用卡打开。
- 时限：单页 8s、单次调用最多 3 页、总 20s 预算。

## 七、模型生成保证

- 图节点：publish 层按模型 decision 生成（reply 全部来自模型）；仅技术错误码
  （超时/认证/解析失败）有固定文案——它们是状态提示，前端按「本轮未能生成回复」
  渲染在错误卡中，不进入聊天记录正文。
- 后端默认值：无整段固定回复。
- 前端组件：上一轮已改造完成（ChatView.vue 按 status 分支渲染模型正文，
  insufficient/out_of_scope 均显示模型写的说明，不换前端预写文案）。
- 修复的两个真实缺陷：
  1. max_tokens 1100 → 2400（长回复 JSON 被 token 截断导致 model_response 失败）；
  2. evidence_ids 超 6 条不再整单丢弃（截前 6 条，发布层校验兜底）。
