我希望修完之后，左边能切校区，中间能看清我选的是哪栋楼，右边能读全名，下面能正常提问。全校夜景、院徽、金色细线和朱砂高亮是现在的特点，继续保留。先修这张图真的有的问题，建议按下面三步依次做，每步做完就用同一个北区画面复看。

开始前

项目是 Vue 3、TypeScript、Pinia、Vite，3D 沙盘用 Three.js。先看 git status，接着别人现有的改动做。读 frontend/src/views/StageView.vue、components/stage/SceneSigns.vue、CollegeLanterns.vue、AskDock.vue、StageHud.vue、CampusPanel.vue、ZdxStar.vue，以及 styles/stage.css 和 theme.css。A2 学院灯牌已落地，A3 等后续设计在 docs/3d/ALIVE.md 和 docs/3d/cards/。如果后续代码已经有院徽题签等实现，直接接上。这个任务集中在 UI 覆盖层，可沿用 StageCanvas 提供的 stageCtx、registerFrame 和 handle.project。保留现有校区、学院、建筑 ID、楼顶 anchor、地图模型、镜头机位和后端接口；本次实现用仓库已有依赖。

原图可直接从对话里的附件查看。若能访问本机文件，可以参照 C:/Users/31978/Desktop/1.png。截图记录的是北区概览，请也验证点「近看」之后北区独立沙盘里的样子。每个阶段都要覆盖日间和夜间。

第一步：先让仍留在屏幕上的字读得清

1. 搜一下 stage.css 的 --st-moon、--st-moon2、--st-moon3 的来源，再看 .stage-mark、.stage-mark-label 和 .stage-lantern-tag。前者在日间会变成墨色，后几处则有固定深底，或者直接叠在夜景地面上。给这些地图覆盖件配一组专用的固定前景和背景色，并把它们集中写在 .stage 范围内。示例值是深墨蓝 #0C1420、正文月白 #E8EDF3、次要字 #B9C3D2、细边和引线用品牌金。背景要足够实，参考 95%–100% 不透明。桌面悬浮标签、小序号的字、学院灯牌悬停签、直接贴在夜景上的状态字和普通按钮使用这套搭配。普通正文与这些底板的对比度以 4.5:1 为验收目标。细线和边框可以更淡。

2. 页面主题仍管顶栏、右边面板和带纸色底的输入框。这些控件用成对的主题前景和背景。日间是暖纸白配墨色，夜间是墨蓝配月白。右侧面板的底色更实一些，当前选中行使用现有朱砂或细线强调。优先保证学院名，必要时用 14–16px 的黑体字、正常字距和 1.4 行高。全名换行，楼名用次一级文字。检查截图中的「信息科学与技术学院」和「农学院农科楼」在面板里不挤在一起。说明、状态、出处不要只靠颜色区别。

3. 对地图上的字用尺寸、底板和间距来保证可读。大校区保留原有竖签。学院悬停名牌改成横排，13–14px、字重 500 或 600，内边距约 6px 10px，长名称最多两行或用已有短名。完整名称由按钮的 aria-label 或侧栏提供。若保留建院年份，只在确有 year 时显示。地图文字尽量都落在自身底板内。明确的 Tab 焦点样式要保留，触屏可以从右侧完整学院列表点选。

4. 星光保留，按现有层级让装饰光晕处于题签与面板下面。星光和文字接近面板、或者挡住选中题签时，优先减弱光晕，必要时收起装饰性的「智多星」字样，保留提问状态提示。先把面板底色修实，再做这一条。像比例尺、罗盘、星光、连接线这类只展示的元素，仍保持合适的 pointer-events 设置，原本能操作的罗盘入口沿用现有点击方式。

验收：停在北区，日间和夜间都能直接读清数字、悬停学院名、右侧名称以及观景、重置、普通版。有亮窗、红色光柱或星光经过时，主要文字还是清楚的。

第二步：让场景只显示该显示的层级

先把默认显示理顺。SceneSigns.vue 目前分别画校区竖签、地标签、W9 学院序号和学院全名。CollegeLanterns.vue 另外会画 A2 院徽、楼顶引线和悬停签。两者使用不同的循环，默认都画就会有重复。

按这里做，已有 data-testid 和点楼逻辑尽量沿用。
- 全校首页，只保留校区题签，学院从选校区后再看。若左上题字露出，把真实题字区域留空。
- 北区等任一校区概览，保留当前校区竖签。一个学院有灯牌时，以院徽做标记，加小号序号与右侧对应，序号可以是角标或贴近底部的小锚点，避免再拼一整条学院全名。悬停或键盘聚焦才出横排短名。没有可用院徽的学院仍有能点的小序号。顺序从现有校区面板与地图标记的共同数据取得，核对编号是否对应同一个 buildingId，别用手写北区顺序。对同楼多学院，沿用现有数据分组和选择路径，能放下时保留并列。太挤时收成一个楼的标记，由面板里的完整条目区分；必要时保留「+N」以及明确的可访问名称。
- 校区独立沙盘里，优先保留已有办事地标。学院灯牌与地标签投到同处时，高优先级标识完整展示，另一项可以收为小标记或从面板查看。当前被选中或聚焦的楼优先。
- 答复定位、点击学院或地点后，优先保留唯一的主楼题签和准确的锚点。若 A3 已有本色院徽，沿用它。选中的楼名用现有题签或清晰的小横签，边框使用朱砂。它被面板挤出空间时，先尝试短标签，再用可见的锚点加右侧面板里的完整位置。
- 观景态、无 WebGL 或静态图继续按现有策略。静态模式仍可读已有文字定位和校区列表。

再做统一避让。默认整理完仍会出现旋转后重叠，再写这一层。建议做一个小的纯 TypeScript 函数，输入是视口、遮挡矩形和一组标签，输出是实际矩形及展示形态。两个标签组件要共用同一份布局结果。可以把协调逻辑放在 StageCanvas 插槽内的小组件或共用 composable，先确认 provide/inject 的位置。固定元素和 handle.project 返回的是浏览器视口 CSS 像素，直接用相同坐标比较。project 已含 canvas 的 left/top，连接线也用同坐标系。

每个候选提供稳定 ID、优先级、楼顶投影 x/y、默认文字框的宽高、紧凑尺寸、关联 buildingId。可以先用明确的 CSS 尺寸和上限，保证计算矩形真的覆盖外显的文字和图标。候选布局按下面的规则选。
1. 建立视口安全矩形，再扣除这次真正可见的顶栏、左侧校区栏及近看按钮、右侧校区/回答面板、底部问话栏及按钮、可见题字。取对应元素 getBoundingClientRect 的位置。给边界留 8–12px，已有面板收起按钮时只记录实际占用。有条件可把读数、比例尺算进去。忽略被隐藏的节点。
2. 同一帧先放定位的楼或键盘聚焦标记，接着放当前校区、悬停标记，再放普通地标和院徽。优先级相同时按稳定 ID 排，避免拖动时顺序反复变。固定控件已有保留区，任何标签都别占它。
3. 一个标签先尝试沿用上一帧安全位置，再试楼顶正上方，然后向上或左右各挪约 24–36px。选一个能放、与已接受的标签矩形有间距的位置。都不合适就尝试只显示小院徽或序号。普通标记连紧凑形态也放不下时，可以暂时收起，右侧面板仍保留对应入口。当前选中/键盘聚焦项优先保留可操作入口。不要让使用 Tab 的人落在看不见的标记上；如果需要收起正在聚焦的一项，将焦点交接到对应可见的列表项。
4. 文字或徽图可以错开，楼顶锚点不动。移动后从标签边缘画短引线指回原锚点，选中楼用朱砂，普通楼用细金线。没有偏移时沿用当前线和锚点。看不见的楼或落在面板下面的锚点，以面板文字定位为准。旧的「距楼顶 ±3px」验证针对真实锚点或引线末端；安全默认位仍按已有几何精度验证。
5. 用现有 registerFrame 跟着相机更新投影。遮挡矩形在尺寸变化、面板显示切换、语言长度或视口变化时集中读一次。可以用现有布局钩子或 ResizeObserver，离开页面记得清理。每帧先算最终结果再提交显示，避免每张牌先改样式又读尺寸。只在输出位置或可见状态变化时更新。镜头平移不应使标签跳到别栋楼，也别因为悬停文字一出现就把鼠标下的按钮挪走。低动效下关闭额外的过渡。

验收：全校点北区，信息学院的灯牌不挡住「北区」，场景里没有两段重复的学院长名。打开和收起右侧面板、旋转、缩放、切中区、回全校，保持定位正确。专门测试两个标签矩形相交、标签在面板下、同楼多个学院、视口边缘和屏外点。只隐藏确实放不下的内容，选中目标和右侧对应行可认出；原先能点的学院仍能从可见入口访问。

第三步：给底部操作排好位置

现在比例尺在 StageHud.vue 里用两点投影的横向差直接当 CSS 长度。全校包一次标的是五百米，缩放后就可能很长。问话栏等控件固定定位，同一空间会被不同元素占用。

- 把底部归成三个可用区域。左边罗盘和短比例尺，中间状态、示例、问话框，右边原有读数。继续留出底图署名。可以用 CSS Grid，也可以保留现在的固定定位，用共享边距和已测量区域做约束。只有短窗口才优先把状态和工具整理到一张窄底板上，允许示例换行。以后手机空间不够，先让次要读数或比例尺按已有降级方式收起，提问、校区和定位入口仍可见。支持现有的普通版和静态模式。
- 观景、重置、普通版按钮和示例问题使用已有交互，给它们成套的文字与底板、hover 和 focus-visible。问话框用当前主题的实底。看同一行是否能清楚读到按钮名。保持输入框和键盘提交顺序。
- 比例尺根据原来校准的投影长度与 meta.look.hud.scaleMeters 换算每米屏幕长度。取一个能放进实际空位的常用单位值，例如 500、200、100、50、20、10 米，使用对应的真实像素长度及文字。桌面可先用约 48–120px 为可读目标，再按实际空位计算。拿不到可靠校准或空位放不下时隐藏这段比例尺。不要用 max-width 剪短原长度却还显示原距离。检查 stopName 的来源，window 上的调试钩子不是 Vue 响应式数据，读取当前停靠点要以实际更新路径为准。静态模式按项目已有方式处理，继续保留底图署名及说明。
- 右侧读数和字幕不盖住输入。切换主题时不用跳动高度。窄视口不出现横向滚动。测试固定比例尺、罗盘或署名区域周围仍能拖动画布。
