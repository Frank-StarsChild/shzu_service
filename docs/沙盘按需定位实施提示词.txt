请在当前「石大智多星」项目里修一下首页沙盘的自动定位。

现场问「你好」，右侧正常回一句话就行，镜头留在我正在看的地方。问「本科生最多能借几本书」，即使回答引用了图书馆的文件，也照常只看答复。问「学生证丢了去哪补办」或者「图书馆在哪」，如果确实找到了当前校区的一栋明确目标楼，再让沙盘帮我飞过去。先看 git status，基于目前的改动继续做，流程图和问话入口照常工作。

一、先查两个触发点

先读 frontend/src/views/StageView.vue、frontend/src/stage/places.ts、frontend/src/stores/stage.ts 和 frontend/src/components/stage/AnswerPanel.vue。打开 /stage?3d=1&intro=0，分别从全景和已经选中的楼栋发一句「你好」。如果真实后端能用，记一下该轮的 answer、actions、citations 和镜头变化。否则用 tests/e2e/fixtures/api.ts 模拟一条问候答复，里面故意提到「图书馆」，再带一条图书馆发布的引用。

当前 resolvePlace() 会依次取动作卡里的第一个有楼号的候选、正文里第一个匹配的楼名、出处发布单位对应的楼。三个来源都可能被当成实际的办理地点。StageView 在 pending 时还调用 showAnswer(null)，从楼栋视角发问可能先飞回全景。两处都需要改。改前先用调试钩子确认你看到的是飞回首页、飞到图书馆，还是右侧面板打开时已有的构图让位。面板让位只改投影，可以保留。

二、把地点和移动镜头的权限分开

在 places.ts 里集中做一次纯函数判断。输入本轮用户问题、ChatResponse、现有地点表和当前地图状态（是否就绪、已选校区、本包楼栋），输出 hold、offer 或 auto，以及可展示的候选。用同一个结果控制自动飞行和右侧定位入口。整件事沿用现有接口和场景数据。

1. hold，保持视角。问候、致谢、闲聊、政策条件、数量、时间、材料清单这类问题默认走这条。比如「你好」「图书馆几点关门」「奖学金要什么条件」都不会给镜头下命令。澄清、超范围、取消和错误继续显示对应的界面。地点只出现在回答正文、流程图、示例问题或出处发布单位时，保留原内容即可。纯问候即使误带一个 place 动作也保持视角。

2. offer，提供手动定位。用户确实在问地点或线下办理，且本轮有可用目标，但结果有多个候选、工具标了 ambiguous、目标跨校区、当前沙盘还没就绪，或者只有用户明确点名的登记楼栋而没有结构化结果时，显示「在沙盘查看」或候选列表。候选使用真实楼号、名称和校区，按楼号去重。用用户问题匹配登记名时，优先完整名称，例如「北区图书馆」包含的「图书馆」不能再算一个命中。多个候选都能选，不能默认点第一条。只有文字地址时就显示文字。用户点击后复用现有 showBuilding、switchPack、waitPackThenShow 或已有的近看路径，跨包只在点击后发生。静态舞台先给可读的位置说明，避免点完进入永远等不到 3D 就绪的状态。

3. auto，自动定位。需要同时满足三个条件。用户明确要找位置或去线下窗口，本轮有唯一的结构化目标，并且目标在当前可见的 3D 场景内。明确的位置问法包括「在哪栋楼」「去哪办」「怎么走」「在沙盘定位」。按整句判断，比如「你好，图书馆在哪」仍然能定位，「图书馆几点关门」和「图书馆的借阅规则在哪看」则保持。只从本轮 place.matches 或 errand.place 取结构化楼号。errand 和 place 指向同一栋楼只算一个目标。响应有冲突、标了 ambiguous 或地点是文字时，按 offer 或 hold 处理。从已选校区问到另一个校区的楼，即使两个校区都在全校模型里，也请学生点一下再过去。镜头已经在目标楼时，只关联本轮答案，不重复飞。

正文里的第一个楼名和 citations 的 issuer 都从自动定位的路径里移除。旧响应仍正常显示原文和依据。对于只问「怎么借书」或「成绩单怎么打印」的用户，让原操作说明照常出现。只有用户明确问「去哪借」「去哪打印」才适用地点判断。澄清选项提交时看到的「[选择] 北区」不能单独算一个定位请求。首版可在澄清完有结构化地点时给手动定位，保持实现简单。

三、消除发问时的回弹

在 StageView 的 pending、失败和无落点分支里，停止用 showAnswer(null) 结束这轮问答。把开始新一轮需要做的事拆出来，例如重新打开右侧回答面板、清掉上一轮的办理地点关联、退出旧的板块内容、作废旧的延时定位。当前地图的 packId、mode、zoneId、已选楼和相机机位保持原值。复用 placeSeq 或现有的请求标记让旧的等包任务作废。如果清 board 就足以让右侧换回答面板，不必借由回 home 来完成。

右侧「办理地点」和它连到楼上的红线，要取本轮已经关联的目标，并与 request_id 对上。不要只看 stage.place，那里也可能是用户早就在看的楼。上一轮选中的楼可以留在地图视野里，当新问题没有地点时，新回答不应再把它写成办理地点。AgentTrace 的引用题签和原文仍可显示。用于标记本轮落楼的红线也跟随实际的本轮关联。直接点沙盘楼栋、学院和校区、输入预判、手动观景、重置视角继续走现成入口。

自动定位只由本页发出的最新一轮触发，历史恢复不会重播。沿用 activeNewRequestId 和现有 trace 定时器，在调用镜头前再检查一次当前 request_id、沙盘和目标。若在等待回答或「核证」动效期间用户已经选了别的楼、换了校区或重置视角，保留刚选的视角，把本轮目标交给手动入口。检查 StageCanvas 是否能直接从 A 楼飞到 B 楼。现在它主要监听 mode、zoneId、collegeNo，两次同属 answer 状态时如果没反应，就把 place.buildingId 纳入现有监听。用一条状态路径应用镜头，避免先调用 home 再飞到目标。

四、按下面的顺序验收

1. 在全校全景问「你好」，再手动点到别的楼、拖动到一个新角度，依次问「你好」「谢谢」「本科生最多能借几本书」「图书馆几点关门」。分别检查发送后和答复后。右侧有内容，校区、机位和原地图选择都稳定，新回答不显示旧办理地点。至少一个模拟响应同时塞进带楼名的正文、图书馆 issuer 和误带的单目的地 place 卡，仍保持视角。
2. 问「你好，学生证丢了去哪补办」，给已有中区办事单和同一楼号的 place 卡，应该只飞一次到大学生活动中心。接着问一个明确的其他楼栋定位，应该直接到下一栋，中间不回全景。再次问同一地点，验证不重复飞。用结构化模拟数据验证「图书馆在哪」能定位，「图书馆能借几本书」保持视角。
3. 从中区问一个北区目标，再试工具返回两个不同楼号。答复先出，镜头不动。点击指定目标后才切，点第二个候选确实到第二栋。给文字地址、静态舞台、未就绪模型各测一次，位置文字仍可读。
4. 模拟慢回应，等待期间手动换校区，再让旧回应返回。确认它不能把人拉回去。再试取消和刷新恢复历史，同样不会重播自动飞行。普通版聊天、流程图、引用和办事单仍能正常使用。

更新 tests/unit/places.test.ts 中明确属于旧规则的断言，例如仅由 issuer 自动到图书馆、多个楼取第一栋。用 tests/e2e/stage-place.spec.ts 和 stage-ask.spec.ts 做浏览器回归。使用 window.__campus3d 的 stop、moving、pack、shell、pin 及项目已有的相机调试字段验证真实视角。至少有一条测试从非 home 开始，确认 pending 和答复后都没有短暂回 home。优先挑需要的测试执行，已有截图用例可能更新文档图片。
