# A7 回答按段输出、零件库（第三批）

**做完的样子**：问「国家励志奖学金要什么条件？」，回答面板不再是一整段字：最上面是办理地点；「条件」是一排带序号的小签；「步骤」是一卷左边一根金线、每步一个金色方块写着「一二三」的卷轴；「材料」是一张能点的勾选清单，全部勾上时右下角盖下一枚朱红的「齐」字章。普通版的页面也按段显示（它本来就支持）。对照 `alive-steps.jpg`。

**原理**：现在后端把模型的整段回答包成一个 `note`（`graph.py` 第 381 行）。改成让模型按段输出、每段标一个类型、每段带自己的证据；页面按类型从固定的零件里挑。模型只决定「这段是什么」，不生成任何界面。

**只许改**：`backend/app/agent/graph.py`、`backend/app/contracts/models.py`（只为 `AnswerBlock.kind` 的注释）、`prompts/02_answer.md`（如果系统提示是从这里读的）、`frontend/src/components/AnswerBlocks.vue`（只许在 `KIND_LABEL` 里加一行 `condition: "条件"`）、`src/components/stage/AnswerPanel.vue`、`src/styles/stage.css`；新建 `src/components/stage/answer/StepScroll.vue`、`MaterialCheck.vue`、`CondChips.vue`、`scripts/check_a7.py`、`tests/unit/blocks.test.ts`、`tests/e2e/stage-blocks.spec.ts`。

## 要做的事

**先跑一遍评测，留底**：后端照常启动，`python evaluation/run_eval.py`，把输出的总分和耗时的中位数、95 分位记进 `PROGRESS.md`（「A7 之前」）。

**后端**

1. **模型的输出**（`graph.py` 的 `ModelDecision` 和 `BASE_PROMPT`）：
   - 新增 `DecisionBlock`：`kind: Literal["office", "condition", "step", "material", "fact", "note"]`，`text: str`（1 到 300 字），`evidence_ids: List[str]`（最多 4 个）。
   - `ModelDecision` 加 `blocks: List[DecisionBlock]`（最多 8 段，默认空）；`reply` 改成可选（默认空字符串）。规则：`status` 是 `answer` 或 `insufficient` 并且涉及校园事实时，写 `blocks`、不写 `reply`；其他情况（纯对话、追问、超出范围、向导）照旧写 `reply`。两者都空的算无效输出（同现在 `reply` 为空的处理）。
   - 提示词里的输出格式改成带 `blocks` 的版本，并说明六种类型：`office` 办理地点和办公室（放在最前面，一段）；`condition` 条件和资格（一条一段）；`step` 步骤（一步一段，按先后）；`material` 要交的材料（一样一段）；`fact` 其他事实；`note` 提醒和说明。**不要让模型同时写 `reply` 和 `blocks`**（输出的字数会翻倍，变慢）。
2. **发布**（`_publish_final`）：
   - 有 `blocks` 时：每段的 `evidence_ids` 必须都在本轮工具返回的证据里，否则这一轮按 `model_output` 出错（同现在的校验）；`citations` 用所有段的证据合起来（去重，保持第一次出现的顺序，最多 `MAX_CITATIONS` 条）；每段的 `citation_ids` 是它自己的证据；`message` 是各段 `text` 用换行连起来（普通版和历史记录都用它）。
   - 只有 `reply` 时：和现在完全一样（一个 `note` 段）。

**前端**

3. **`AnswerBlocks.vue`**（普通版）：`KIND_LABEL` 加一行 `condition: "条件"`。别的不动。
4. **舞台的回答面板**（`AnswerPanel.vue`）：把 `answer.blocks` 里**连着的同一种 `kind`** 合成一组，按出现的顺序画：

   | `kind` | 小标题 | 零件 |
   |---|---|---|
   | `office` | 办理地点 | W5 的地点行（有学院的走 A3 的样子）；这一组的文字放在楼名下面，12.5px 月白 66% |
   | `condition` | 条件 | `CondChips`（`stage-conds`）：每段一个小签，1px 淡金边，12.5px；前面一个金色 600 的中文序号 |
   | `step` | 步骤 | `StepScroll`（`stage-steps`）：左边距 30px，一根 1px 淡金竖线；每步前面一个 21×21 的金色方块，里面宋体 700 11.5px 墨色的中文序号 |
   | `material` | 材料 | `MaterialCheck`（`stage-materials`）：每段一行（`stage-material-<序号>`，从 1 起），前面一个 14×14 的方框（1px 金色 55% 内描边）；点一行切换勾选：勾上时方框填金色、里面一个墨色的勾（用两条边框转 45 度画，不用字符），文字变成月白 66%。全部勾上时，清单右下角出现「齐」字章（`stage-materials-seal`）：64×64 的圆，2.5px 朱红边，里面再一圈 1px 朱红细边，宋体 900 25px 朱红「齐」，转 −14 度，不透明度 0.9，用 A9 盖章的同一个动画；取消任何一项就消失 |
   | `fact` | 回答 | W4 原样 |
   | `note` | （没有小标题） | 13px 月白 66% |

   - 每段文字后面照旧带引用角标（W4 的做法）。
   - 没有 `office` 段但 `place` 不为空时，照旧在最上面画 W5 的地点行。
   - 勾选状态只放在这个组件的内存里，换了回答就清空。
5. `resolvePlace` 不用改：它本来就按段的顺序找，`office` 在最前面，自然先找到。

## 常见错误

- 让模型既写 `reply` 又写 `blocks`：输出变长一倍，耗时上去，A10 白做。
- 评测分数降了就去改题目或放宽评分：不许。分数降了说明提示词要调，停下来问人。
- 勾选清单用了 ✓ 字符：规则里不用图标和符号字符，勾用两条边框画。
