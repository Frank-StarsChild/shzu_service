# W6 把首页换成舞台

**做完的样子**：打开网站首页就是舞台。手机、没有显卡的电脑、窄窗口、关掉 3D 的用户，首页还是原来的白色页面。舞台顶栏的「服务」「普通版」都能点；普通版顶栏多一个回到舞台的入口。

**只许改**：`src/router/index.ts`、`src/App.vue`、`src/views/StageView.vue`、`src/components/stage/StageTop.vue`、`src/styles/stage.css`；新建 `src/stage/entry.ts`、`src/views/EntryView.vue`、`tests/unit/entry.test.ts`、`tests/e2e/stage-entry.spec.ts`。下面「旧测试要改的地方」列出的文件。

## 要做的事

1. **`entry.ts`**，纯函数：

```ts
export type EntryInput = {
  mode: 'static' | 'scene';       // 现有 decideMode() 的结果
  viewportWidth: number;
  queryStage: '1' | '0' | null;   // 地址栏 ?stage=
  prefer: 'classic' | null;       // localStorage 的 shzu.stage 是否为 'classic'
};
export function decideEntry(input: EntryInput): { stage: boolean; reason: string };
```

   规则从上到下，命中第一条就返回：

| 序 | 条件 | stage | reason |
|---|---|---|---|
| 1 | `queryStage === '0'` | false | `query-off` |
| 2 | `mode === 'static'` | false | `static` |
| 3 | `viewportWidth < 1100` | false | `narrow` |
| 4 | `queryStage === '1'` | true | `query-on` |
| 5 | `prefer === 'classic'` | false | `prefer-classic` |
| 6 | 其余 | true | `default` |

2. **`router/index.ts`**：
   - 路由 `/` 的组件改成一个很薄的壳 `src/views/EntryView.vue`（新建，只许包含下面的逻辑）：挂载时算一次 `decideEntry`，`stage` 为真渲染 `StageView`，否则渲染 `HomeView`。两个都用 `defineAsyncComponent` 动态加载，**普通版的用户不该下载舞台的代码**。
   - `/` 的 `meta.stage` 不能写死。改成：`EntryView` 决定用舞台时，给 `document.documentElement` 加 class `is-stage`，离开时去掉；`App.vue` 里顶栏和页脚的 `v-if` 改成同时看 `route.meta.stage` 和这个 class（用一个响应式变量同步它）。
   - 新增路由 `/classic`，组件是 `HomeView`，`meta.title` 是「服务入口」。
   - `/stage` 保留（测试一直在用）。
3. **`StageTop.vue`** 的导航变成真的：
   - 「问答」：让输入框获得焦点。
   - 「服务」：去 `/services`（服务目录页，办事向导的入口也在那里）。
   - 「普通版」：把 `localStorage` 的 `shzu.stage` 设为 `'classic'`，去 `/classic`。
   - 「观景」：这张卡里先不响应（W8 做）。
4. **`App.vue`** 的普通版顶栏：在导航最后加一项「校园」，链接到 `/?stage=1`。只在 `decideMode()` 为 `scene` 且视口宽度不小于 1100 时显示。点它时把 `localStorage` 的 `shzu.stage` 删掉。
5. 窗口从宽拖到窄于 1100 不用实时切换，下次进入首页时再判断。

## 验证

`tests/unit/entry.test.ts`：六条规则每条一例，再加两例：`{ mode: 'static', queryStage: '1' }` 得到 `static`（没有 3D 能力时强制不了）；`{ mode: 'scene', viewportWidth: 1099 }` 得到 `narrow`。

`tests/e2e/stage-entry.spec.ts`：
1. 1440×900 打开 `/?3d=1`：`stage` 可见，没有 `.topbar`；`window.__campus3d.pack === 'all'`。
2. 1440×900 打开 `/?3d=0`：`h1.h-display` 含「校园办事」，`.board-tile` 恰好 5 个，没有 `stage`。
3. 1000×800 打开 `/?3d=1`：同第 2 条（窄窗口走普通版）。
4. 1440×900 打开 `/?3d=1`，点「普通版」：地址是 `/classic`，`.topbar` 在，`.board-tile` 5 个。再打开 `/?3d=1`：仍是普通版（记住了选择）。点普通版顶栏的「校园」：`stage` 可见。
5. 在舞台上点「服务」：地址是 `/services`，`.topbar` 在，页面背景是白色。点浏览器后退：回到舞台，`status` 最终是 `ready`。
6. 在第 2 条的页面上检查网络请求：没有请求过 `campus.glb`，也没有加载过文件名含 `StageView` 的脚本。
7. 在舞台上问一个问题，点「进入向导」或「全部对话」离开，再后退：面板里还是刚才那一轮回答，镜头在首页机位（不重新飞）。

**反向验证**：把规则 3 的 1100 临时改成 900，第 3 条必须变红；改回。

## 旧测试要改的地方

舞台成了首页，以前直接打开 `/` 并期望看到白色首页的测试会变红。**只许做这一种修改**：把这些测试里的 `page.goto('/')` 换成 `page.goto('/classic')`，带参数的（例如 `/?3d=1`）换成 `/classic?3d=1`。逐条记进 `PROGRESS.md`。涉及的文件：`baseline.spec.ts` 的前三条，以及首页沙盘（`CampusHero`）相关的各个 spec。

如果换了地址以后还有测试变红，是代码的问题，停下来查，不要再改测试。

## 常见错误

- `StageView` 被打进了首屏的包：用了静态 `import`。第 6 条会红。
- 从服务页后退回舞台，画布是黑的：`StageCanvas` 被 `keep-alive` 缓存了但场景已经释放。不要对它用 `keep-alive`，回来时重新创建。
- 普通版的 `/classic` 也没有顶栏：`is-stage` 这个 class 离开舞台时没有去掉。
- 手机上打开首页是黑屏：`decideEntry` 没有先看 `mode === 'static'`。
