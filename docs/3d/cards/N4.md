# N4 开场动画和镜头入场

**做完的样子**：3D 准备好的那一刻，画面里先是空地上的线框，线框立起，楼从图书馆向外一栋栋长出来，树冒出来，光柱点亮；镜头同时从高处落下，停在默认机位。全程 2.7 秒。对照 `docs/3d/reference/intro-*.jpg`。

**原理**：这段动画已经做在模型文件里，是一个名叫 `meta.look.intro.clip` 的动画片段。代码只负责播放一次。

**只许改**：`src/campus3d/gate.ts`、`src/campus3d/scene.ts`、`src/components/CampusHero.vue`、`tests/unit/gate.test.ts`、新建 `tests/e2e/intro.spec.ts`，以及下面「旧测试要改的地方」列出的文件。

## 要做的事

1. **要不要播，写成纯函数**（放在 `gate.ts`）：

```ts
export type IntroInput = {
  queryIntro: '1' | '0' | null;   // 地址栏 ?intro=
  played: boolean;                // sessionStorage 的 shzu.campus3d.intro 是否为 '1'
  reducedMotion: boolean;
  hasClip: boolean;               // 模型里有没有这个片段
};
export function decideIntro(input: IntroInput): { play: boolean; reason: string };
```

   规则从上到下，命中第一条就返回：

| 序 | 条件 | play | reason |
|---|---|---|---|
| 1 | `hasClip` 为假 | false | `no-clip` |
| 2 | `reducedMotion` | false | `reduced-motion` |
| 3 | `queryIntro === '0'` | false | `query-off` |
| 4 | `queryIntro === '1'` | true | `query-on` |
| 5 | `played` | false | `played` |
| 6 | 其余 | true | `first-visit` |

   同一个浏览器标签页里只自动播一次（回到首页不再播）；`?intro=1` 用来强制重播，录演示视频时用。

2. **`scene.ts`**：`createCampusScene` 的 `opts` 增加 `playIntro: boolean`。为真时：
   - 画第一帧**之前**：把相机放到 `meta.look.intro.cameraFrom`；用 `AnimationMixer` 取出片段（`AnimationClip.findByName`），设置成**只播一次、播完停在最后一帧**，开始播放，并把动画时间设到 0。这样第一帧就是动画的起点。
   - 第一帧画完，`createCampusScene` 照常 resolve。
   - 之后每一帧：`mixer.update(dt)`，`dt` 是离上一帧的秒数，大于 0.1 时按 0.1 算。
   - 同时调用镜头移动到 `overview`，用时 `meta.look.intro.cameraMs` 毫秒。为此给 `goTo` 的选项加一个 `durationMs`（不传时仍是 900）。
   - 片段播完（混合器的 `finished` 事件）**并且**镜头到位后，开场结束：回调通知外壳，并且不再调用 `mixer.update`。
   - 开场期间用户悬停板块按钮：照常 `goTo` 过去，不用等。此时「镜头到位」按新的目标算。
   - `AnimationMixer`、`AnimationClip`、`LoopOnce` 从 `three` 引入，不装新依赖。
3. **`CampusHero.vue`**：
   - 模型加载完、创建场景之前，用 `decideIntro` 判定。
   - `play` 为真时：`status` 先置为 **`intro`**（新增的状态），画布照常 400 毫秒淡入；开场结束后 `status` 置为 `ready`，并把 `sessionStorage` 的 `shzu.campus3d.intro` 写成 `'1'`。
   - `play` 为假时：和以前完全一样，直接 `ready`。
   - `status` 为 `intro` 时：加载条隐藏，标记照常跟随，N3 的循环条件里把「`status` 是 `ready`」放宽成「`status` 是 `ready` 或 `intro`」。
   - 开场期间如果画框滚出了视口或页面切到后台：直接跳到结尾（动画时间设到片段末尾，相机直接放到目标），然后 `ready`。
4. **调试钩子**：`status` 的取值增加 `'intro'`；新增 `intro`（`'none' | 'playing' | 'done' | 'skipped'`，没判定前是 `none`）、`introReason`（`decideIntro` 的 `reason`）、`nodeScaleY(name)`（返回模型里这个名字的节点当前的 `scale.y`，找不到返回 `null`）。

## 验证

`tests/unit/gate.test.ts` 增加：`decideIntro` 表里 6 行各一条；再加两条优先级：`reducedMotion` 且 `queryIntro='1'` → `reduced-motion`；`played` 且 `queryIntro='1'` → `query-on`。

`tests/e2e/intro.spec.ts`：
1. `/?3d=1`：先出现 `status === 'intro'`（此时 `intro === 'playing'`），之后出现 `status === 'ready'`（此时 `intro === 'done'`）。两者相隔不少于 2 秒、不多于 8 秒。
2. `/?3d=1`：刚进入 `intro` 时立刻读 `nodeScaleY('FX_beacons')`，小于 0.5（光柱在第 1.95 秒才开始升起）；`ready` 后，`nodeScaleY` 对 `L_edges`、`FX_beacons`、`S_props` 和任选 3 个 `B_` 节点（从 meta 的 `buildings` 里取）都在 0.999 到 1.001 之间。
3. `/?3d=1`：`ready` 后 `stop === 'overview'`，`camera.position` 与 `meta.stops.overview.position` 各分量相差小于 0.5；5 个标记的中心与 `projectPoint(anchor)` 相差小于 3 像素。
4. `/?3d=1`：`ready` 后 `sessionStorage` 里 `shzu.campus3d.intro` 是 `'1'`。点导航去「服务目录」，后退，等 `ready`：这一次 `introReason === 'played'`，全程没有出现过 `status === 'intro'`。
5. `/?3d=1&intro=0`：`introReason === 'query-off'`，`intro === 'skipped'`，直接 `ready`。
6. `emulateMedia({ reducedMotion: 'reduce' })` 后 `/?3d=1`：`introReason === 'reduced-motion'`，`ready` 后各节点 `nodeScaleY` 为 1。
7. `/?3d=1`：进入 `intro` 后立刻悬停「图书馆」按钮：最终 `status === 'ready'`，`stop === 'lib'`，`hotVisible` 正确，控制台没有 error。
8. 之前所有测试仍然全绿（改过的见下）。

截图：`intro` 开始后 0.6 秒和 1.4 秒各截一张画框，存 `docs/3d/shots/N4-intro-a.png`、`N4-intro-b.png`。

## 旧测试要改的地方

旧测试都是等 `status === 'ready'` 再做事，开场期间 `status` 是 `intro`，所以它们会自动多等不到 3 秒，**不需要改**。只有两处例外：

- `budget.spec.ts` 第 2 条「从开始导航到 `ready` 不超过 8 秒」：改成用 `/?3d=1&intro=0` 打开，阈值不变。
- 如果某条旧测试自己设了小于 15 秒的等待 `ready` 的超时，把超时改成 20 秒。

## 常见错误

- 播完楼缩回去、或者动画一直循环：见 `NIGHT.md` 第 9 节第 6 条。
- 开场期间 `status` 直接是 `ready`，旧测试在镜头还没落下时就去量位置，大面积变红。
- 第一帧画的是完整的城市，下一帧才跳到动画起点，画面闪一下。动画时间要在画第一帧之前设到 0。
- 开场结束后还在每帧 `mixer.update`。
- 把 three 的对象（混合器、动作）放进了 Vue 的响应式状态。
