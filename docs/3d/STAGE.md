## 1. 做成什么样

**一句话**：网站打开就是一张摆在乌木案台上的夜景校园沙盘，占满整个屏幕；问话栏一直在屏幕底部；智多星是悬在校园上空的一颗星。问一句，镜头飞到办事的那栋楼，楼变红，回答的面板用一根红线连着它。

参考图在 `docs/3d/reference/stage/`：

| 文件 | 画面 |
|---|---|

| `stage-campus.jpg` | 点了左侧「北区」：镜头落到北区，界线变红，题签右边多出「近看」，右边列出北区的学院 |
| `stage-near.jpg` | 点了「近看」：换成北区自己的沙盘，题字是「北区」，地标楼各顶着一块小题签 |
| `stage-zq.jpg`、`stage-by.jpg`、`stage-nq.jpg`、`stage-dq.jpg`、`stage-jjs.jpg` | 另外五个校区各自的沙盘 |
| `stage-answer.jpg` | 问「学生证丢了，去哪补办？」之后：大学生活动中心变红，面板连着它，出处是两张盖了章的公文卡 |

参考图是协助方用同一套资产演出来的示意。里面回答的文字、「79 条审定证据」这类数字是示意值，页面上要显示接口返回的真实内容。

用户看到的过程：

1. 打开首页。先是整屏的夜景海报，3D 准备好后淡入，播开场动画：全校的楼从中区向外一片片长出来，五根光柱点亮，镜头从高处落下。
2. 左上是题字「校园办事，问一次就清楚。」，左边一列竖排的校区题签，底部是问话栏，右下是读数，左下是罗盘。每个校区上方悬着一块竖排的小题签。
3. 点一个校区的题签：镜头飞到那个校区，校区的界线变成红色，面板里列出这个校区的学院，题签旁边出现「近看」。点「近看」：换成这个校区自己的沙盘，楼更大、更细，题字换成校区的名字，地标楼各顶着一块小题签。将军山不在全校沙盘上，点它直接换成将军山校区的沙盘。点「全校」回到全校沙盘。
4. 在问话栏里提问：智多星开始闪动；回答回来后，镜头飞到办事的楼，楼变红（或立起红色光柱），楼上方展开一块题签，右边滑出回答面板，一根红线把「办理地点」那一行和楼连起来。
5. 点右上角「观景」：界面隐去，镜头绕着校园慢慢转。录演示视频用它。
6. 手机、没有显卡的电脑、关掉 3D 的用户：看到现在的白色页面（下文叫「普通版」），功能一样不少。

## 2. 为什么这样设计（答辩时作者要能讲）

- 命题要求回答给出「办理步骤、所需材料、**办理地点**、官方文件出处」。办理地点是聊天机器人给不出画面的东西，也是 3D 真正有用的地方：**3D 在这里是指路，不是装饰**。
- 评委现场打字提问、盲测 50 题、要求 5 秒内响应。所以问话栏始终在屏幕上，问答一步就到，不需要先在 3D 里走到哪里去。
- 命题要求手机也能顺畅打开对话。所以现有的白色页面原样保留，舞台只是在它之上多出来的一层。**舞台出任何问题，普通版都能用。**

## 3. 设计语言：中式科技感，加一点拟物

**一句话**：实体的沙盘加全息的光。沙盘和案台上的东西是实物（乌木、铜牌、印章、公文纸），光是科技（轮廓线、光柱、星）。文字以中文为先。

### 3.1 五种颜色

全部写成 CSS 变量，放在 `src/styles/stage.css` 的 `.stage` 选择器下（不要放进 `:root`，免得影响普通版）。

| 变量 | 值 | 叫法 | 用在哪 |
|---|---|---|---|
| `--st-ink` | `#05080d` | 墨 | 背景。等于 `meta.background` |
| `--st-moon` | `#e8edf3` | 月白 | 文字。次要文字用 66% 不透明度（`--st-moon2`），提示文字用 38%（`--st-moon3`） |
| `--st-red` | `#e2001a` | 朱砂 | **只给两样东西**：印章，和「选中」（选中的校区、办事的楼、当前导航项） |
| `--st-gold` | `#e8c98a` | 鎏金 | **只做细线和小字**：题签的顶边、面板的包角、小标题、顶栏下面那道线。55% 不透明度是 `--st-gold2`，22% 是 `--st-gold3` |
| `--st-paper` | `#efe8d8` | 宣纸 | **只给公文卡和用户问的那句话**。纸上的字用 `--st-paper-ink`：`#1b1a17` |

另有两个派生值：面板底色 `--st-glass`：`rgba(7, 10, 15, 0.78)`；公文卡上的章用深一点的红 `#c4001a`。

### 3.2 三种字

| 变量 | 值 | 用在哪 |
|---|---|---|
| `--st-song` | `"Songti SC", "STSong", "SimSun", "Noto Serif CJK SC", serif` | 宋体。题字、题签、面板标题、小标题、公文卡标题、导航 |
| `--st-hei` | `"PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif` | 黑体。正文、说明 |
| `--st-mono` | 沿用现有的 `var(--mono)` | 等宽。**只给阿拉伯数字**（楼数、秒数、经纬度、时间） |

不下载任何字体文件。宋体标题一律加字距（`letter-spacing` 0.1em 到 0.4em，各零件的值见第 4.2 节）。

### 3.3 八个零件

| 零件 | 样子 | 用在哪 |
|---|---|---|
| **印章** | 朱红方印，白文「智多星印」。直接用 `campus3d/ui/seal.svg`，38×38 | 顶栏最左，品牌标记 |
| **题签** | 窄长的竖排标签：`writing-mode: vertical-rl`，宋体，顶边 2px 金线，其余三边 1px 淡金线，底色近黑。选中时边线变朱红 | 左侧的校区列表和「近看」；场景里悬在校区和楼上方的标签；校区沙盘里地标楼的小题签 |
| **问话栏** | 底部居中的一条：左边输入，右边一方朱红的「问」字钮。上沿 1px 亮线、下沿 1px 暗线，像一块压在案台上的镇纸 | 提问 |
| **包角面板** | 墨色半透明玻璃，四个角各有一个 14×14 的金色直角包角 | 回答、校区的学院列表 |
| **公文卡** | 宣纸色的小卡片，顶边是 3px 的红色双线（红头），标题用宋体，右侧盖一枚「已审定」圆章（`campus3d/ui/stamp.svg`，50×50，逆时针转 12°） | 回答的每一条官方出处 |
| **罗盘和比例尺** | `campus3d/ui/compass.svg`，76×76，「北」字跟着镜头的方位转；旁边一段比例尺，写「五百米」 | 左下角 |
| **读数** | 四行右对齐的小字：沙盘名、北纬东经、楼数和校区数、时辰加时间 | 右下角 |
| **智多星** | 一个 10px 的白色光点，带蓝白色光晕和一个十字星芒；旁边三个宋体字「智多星」 | 悬在校园上空，回答时飞到楼上 |

### 3.4 规矩

1. **中文为先。** 界面上不出现成句的英文。数字用阿拉伯数字，序号用「一二三」。
2. **朱砂只给印章和选中。** 没有选中任何东西时，除了顶栏的印章、「问」字钮、沙盘铭牌上那枚小印，画面里没有红色。
3. **鎏金只做线和小字**，不做大面积的底色，不做按钮底色。
4. **全部直角**，唯一的圆是「已审定」章、罗盘和星。
5. **不用图标库，不用表情符号。** 需要图形的地方只有三个 SVG 零件。
6. **渐变只许用在这几处**：三块遮罩（顶栏从上往下淡出、画面四周的暗角、首页题字底下从左往右淡出）；细线的淡出（顶栏下面的金线、题签底下那根线）；问话栏的底色从上到下略微变暗；星。面板、卡片、按钮的底色不许用渐变。
7. **拟物只有这几处**，不要再加：3D 里的乌木底座、鎏金嵌线、铜铭牌（都已经做进模型）；界面里的印章、公文卡的纸和章、问话栏上下沿的两道压边、「问」字钮按下时下沉 1px。

## 4. 页面结构

### 4.1 层（从下到上）

| 层 | 内容 | `z-index` |
|---|---|---|
| 画布 | 海报 `img` 和 3D `canvas`，`position: fixed; inset: 0`，占满视口 | 0 |
| 暗角 | 一个不接收鼠标的 `div`，径向渐变：中心透明，四周 `rgba(2, 4, 8, 0.66)` | 1 |
| 连线 | 一个占满视口、不接收鼠标的 `svg`，画红色引线和星的拖尾 | 2 |
| 场景标签 | 悬在校区、楼上方的题签和序号标记，位置每帧由 `project()` 算 | 3 |
| 界面 | 顶栏、校区列表、题字、问话栏、面板、罗盘、读数、星 | 4 |

海报用 `object-fit: cover; object-position: 50% 50%`。3D 的竖直视角固定用 `meta.camera.fov`，不随窗口变。海报比任何常见窗口都宽（2.4 比 1），所以两者对得上：窗口变窄时，海报和 3D 都是左右各裁掉一样多。窗口宽高比超过 2.4 时，画布宽度取高度的 2.4 倍并水平居中。

### 4.2 布局（视口宽度不小于 1100px 时；更窄的用普通版）

| 零件 | 位置和尺寸 | 字 |

| 导航 | 顶栏右侧：问答、服务、观景、普通版。当前项白色加 2px 朱红下划线 | 宋体 15px 字距 0.2em；「普通版」是 12px 黑体加 1px 淡金边框 |
| 校区列表 | 左边缘 26px，垂直居中，一列题签，间距 8px。每个题签宽 40px | 校区名宋体 600 15px 字距 0.3em；下面一行小字（楼数，「全校」写「六校区」），9.5px |

| 罗盘 | 左 92px，下 34px，76×76 | |
| 比例尺 | 左 184px，下 40px | 宋体 12px 字距 0.3em |
| 读数 | 右 30px，下 30px，右对齐 | 11.5px 字距 0.2em；第一行宋体 600 13px |

### 4.3 四种状态

状态放在一个 Pinia store 里（第 6.3 节），是唯一来源。

| 状态 | 什么时候 | 镜头 | 3D 里亮什么 | 界面显示什么 |
|---|---|---|---|---|
| `home` | 刚打开；点「全校」；刚换到一块沙盘；开始新的一问之前 | 停靠点 `home` | 无 | 题字、问话栏和示例问题。全校沙盘：场景里五块校区题签。校区沙盘：场景里每栋地标楼一块小题签 |
| `campus` | 点了某个校区（它在当前沙盘上） | 那个校区的停靠点（当前沙盘的 `zones[].stop`，没有这个字段就用 `overview`） | 那个校区的 `Z_` 组 | 题字隐去；场景里只留这个校区的题签（选中样式）；面板列出这个校区的学院；在全校沙盘上时左侧多一块「近看」 |
| `answer` | 收到一条回答，并且找到了办事的楼 | 那栋楼的近景机位（`meta.focus[楼号]`） | 那栋楼的 `H_` 组；没有 `H_` 的楼用图钉 `P_pin` | 题字隐去；回答面板；楼上方的题签；红色引线；用户的问话 |
| `tour` | 点了「观景」 | 绕当前目标点匀速转 | 保持进入时的样子 | 只留一个「退出观景」的小钮 |

收到回答但**没有找到楼**时：状态不变，镜头不动，只弹出回答面板（没有「办理地点」那一行，没有引线）。

「当前是哪块沙盘」是另一个字段（`packId`），和这四种状态是两回事：七块沙盘每一块都有这四种状态，走同一段代码。

### 4.4 动效

| 动作 | 时长 | 说明 |
|---|---|---|
| 镜头飞行 | 沿用现有的 900 毫秒 | 不变 |
| 面板进场 | 260 毫秒 | 从右边 16px 处滑入并淡入 |
| 题签展开 | 260 毫秒 | 用 `clip-path` 从顶边往下展开 |
| 题字隐去、出现 | 300 毫秒 | 只改不透明度 |
| 星飞到楼上 | 900 毫秒 | 和镜头同时开始；位置每帧由 `project()` 算，所以只要改它跟随的那个场景点 |
| 星闪动（等回答时） | 每 1.2 秒一次 | CSS 动画，只改光晕的大小和不透明度 |

系统开了「减少动态效果」时：以上全部改成立即完成，星不闪动，观景不可用。

| 页面最底一行小字 | `meta.attribution`（署名和「非测绘成果」的说明，必须显示） |

### 4.6 普通版

- 现有的 `HomeView`、`ChatView`、`ServicesView`、`WorkflowView`、`SourceView` **一个字都不改**，它们就是普通版。
- `decideMode()` 判定为静态的设备（手机、软件渲染、省流量、用户关掉 3D），以及视口宽度小于 1100px 的窗口，首页走普通版。
- 舞台上点「服务」、点面板里的「进入向导」「看原文」「全部对话」，去的是普通版的页面。从那些页面后退，或者点顶栏的「校园」，回到舞台。

## 5. 资产包 v3 契约

**资产包不许改。** 校验值在 `docs/3d/ASSET_SHA256_V3.txt`。

### 5.1 文件

都在 `frontend/public/campus3d/` 下。原来根目录里的 v2 四个文件原样保留，`NIGHT.md` 的首页沙盘继续用它们。

```
campus3d/
  packs.json                 有哪些沙盘、每块沙盘上有哪些片区、六个校区各自的沙盘是哪一块
  places.json                回答里的地点对到哪栋楼
  all/                       全校：北苑新区、北区、中区、南区、东区，加第一附属医院和护士学校，303 栋楼
  by/                        北苑新区，35 栋楼
  bq/                        北区，109 栋楼
  zq/                        中区，45 栋楼
  nq/                        南区 40 栋楼，一并做了相邻的第一附属医院（56 栋）和护士学校（6 栋）
  dq/                        东区，12 栋楼
  jjs/                       将军山校区，19 栋楼
    （每个目录里都是这四个文件）campus.glb  campus.meta.json  poster-desktop.jpg  poster-mobile.jpg
  ui/
    seal.svg  stamp.svg  compass.svg
```

七块沙盘各自的四个文件，名字、节点命名、`campus.meta.json` 的结构，都和 v2 完全相同，**现有的 `createCampusScene` 换一组地址就能加载**。v3 只是多了几个字段和几种节点。

七块沙盘的关系：`all` 是总的一块，打开网站先看到它，回答也优先落在它上面；六个校区另外各有一块近看的沙盘，范围小、楼大、贴图细，红色外壳配得更全。页面上任何时候只加载一块，换沙盘时先释放旧的。根目录那套 v2 的中区包和这里的 `zq` 是两回事：v2 给普通版首页的画框用，`zq` 给舞台用，互不替代。

### 5.2 `packs.json`

```jsonc
{
  "version": "v3",
  "default": "all",
  "packs": [                                     // 七块沙盘
    { "id": "all", "name": "全校", "dir": "all/",
      "zones": ["BY", "BQ", "ZQ", "NQ", "DQ", "FY", "HX"],   // 这块沙盘上有哪些片区

      "meta": "all/campus.meta.json", "glb": "all/campus.glb",
      "posterDesktop": "all/poster-desktop.jpg", "posterMobile": "all/poster-mobile.jpg", "version": "v3" },
    { "id": "bq", "name": "北区", "dir": "bq/", "zones": ["BQ"], "buildings": 109,
      "note": "食品学院、信息科学与技术学院、生命科学学院、继续教育学院在这里。", … },

  ],
  "campuses": [                                  // 六个校区，顺序就是左侧列表的顺序
    { "id": "BY", "name": "北苑新区", "pack": "by", "buildings": 35 },     // pack：这个校区自己的沙盘
```

地址都相对于 `/campus3d/`。

怎么用这张表（W3 的全部规则都从这里来）：

- **默认沙盘**是 `default` 那一块（`all`）。
- **一个校区在不在当前沙盘上**：看当前沙盘的 `zones` 里有没有它的 `id`。五个主校区在 `all` 上，也各在自己的沙盘上；将军山只在 `jjs` 上。
- **一个校区自己的沙盘**：`campuses[].pack`。
- `nq` 上有三个片区。第一附属医院（`FY`）、护士学校（`HX`）是附属单位，不是校区，不出现在左侧列表里；它们的楼照样能被回答指到。
- `name`、`note` 也给界面用：校区沙盘首页的题字（第 4.5 节）。

### 5.3 `campus.meta.json` 新增的字段

v2 的字段（`version`、`attribution`、`background`、`camera`、`stops`、`hotspots`、`buildings`、`look`）含义不变。新增：

```jsonc
"pack":  { "id": "all", "name": "全校", "aspect": 1.7778, "posterAspect": 2.4 },
"zones": [                                       // 这个沙盘里的片区
  { "id": "BQ", "name": "北区", "kind": "校区", "buildings": 109,
    "node": "Z_BQ",                              // 选中这个片区时要显示的组
    "label": [0, 0, 0],                          // 片区题签的标记点（场景坐标）
    "stop": "bq" }                               // 片区的停靠点。很多片区没有这个字段，没有就用 overview
],
"colleges": [                                    // 楼在这个沙盘里的学院
  { "no": 5, "name": "信息科学与技术学院（网络空间安全学院）", "zone": "BQ", "buildingIds": ["BQ-B013"], "confirmed": true }
],
"shells": ["ZQ-B023", "ZQ-B024", …],            // 配了红色外壳（H_ 组）的楼
"focus":  { "ZQ-B023": { "position": [0, 0, 0], "target": [0, 0, 0] }, … },   // 每栋楼一个现成的近景机位
"buildings": { "ZQ-B023": { "name": "…", "category": "…", "anchor": [0, 0, 0], "zone": "ZQ" } },   // 多了 zone
"stops":  { "overview": {…}, "home": {…}, "bq": {…}, … },                    // 多了 home（首页用）和各片区的停靠点
"look": {
  …,                                             // v2 的字段都在
  "zone":  { "nodePrefix": "Z_" },
  "pin":   { "node": "P_pin" },
  "star":  { "home": [0, 0, 0], "lift": 95 },    // 星平时悬在哪；到了楼上比楼的 anchor 高多少
  "sign":  { "lift": 70 },                       // 楼的题签的标记点比楼的 anchor 高多少
  "tour":  { "degPerSec": 3 },                   // 观景时镜头每秒转多少度
  "orbit": { "minPolarDeg": 35, "maxPolarDeg": 72, "minDistance": 300, "maxDistance": 3600 },
  "hud":   { …, "scaleMeters": 500, "scaleLabel": "五百米" }                  // scale100 里每对点的间距现在是 scaleMeters 米
}
```

上面的数字是占位，真实值以文件为准。**代码里用到的数字和文字一律从这两个 JSON 读，不许写死。**

- `focus` 里的近景机位是给 16 比 9 的整屏画面定的：楼落在画面左中（大约横向 40%、纵向 52% 处），右边留给面板。直接把它传给 `goTo`。
- `hotspots` 在 `all` 里是五个校区各一栋有代表性的楼；在六块校区沙盘里是这个校区的**地标楼**（五到七栋，例如中区是学工、教务、后勤、保卫、图书馆五个办事的地方，加博学楼、知行楼）。它们的光柱（`FX_beacons`）一直亮着，这是对的。舞台上只在校区沙盘的首页用到它们：给每一项画一块小题签，文字是 `board`，位置是 `anchor`（W3）。联动仍然看 `zones`、`shells`、`focus`。
- 只有一个片区的沙盘（`by`、`bq`、`zq`、`dq`、`jjs`），片区没有 `stop`，选中它时镜头去 `overview`。`nq` 的南区有自己的 `stop`。

### 5.4 模型里新增的节点

| 节点名 | 是什么 | 怎么用 |
|---|---|---|
| `H_<楼号>` | 红色外壳加红色光柱，和 v2 一样。`all` 里有 29 个；校区沙盘里，这个校区叫得出名字的楼基本都有（各包的数目见第 5.7 节）。以 `meta.shells` 为准 | 缩放改成 1 显示，改回 0 隐藏 |
| `Z_<片区号>` | 选中片区用的组：一圈红色界线加一根粗的红色光柱。文件里缩放是 `[0, 0, 0]` | 同上 |
| `P_pin` | 通用图钉：一根红色光柱加光圈，原点在地面。文件里缩放是 `[0, 0, 0]` | 先把它的 `position` 设成 `(楼的 anchor.x, 0, 楼的 anchor.z)`，再把缩放改成 1 |
| `L_zones` | 各片区的金色界线，一直显示 | 不用管 |

- `H_`、`Z_`、`P_pin` 都是直接挂在模型根节点下的组（`Object3D`），不是 Mesh。
- 它们的光柱和光圈也用 `FX_` 那张共用贴图，N3 做的「每帧滚动一张贴图」对它们同样生效，不用另写。
- 开场动画的片段名仍然是 `meta.look.intro.clip`。`all` 里有 310 条通道，照 N4 的做法播放即可。
- 同一栋楼在 `all` 和它校区的沙盘里**楼号相同、坐标不同**（每块沙盘的原点在自己的中心）。坐标、机位一律从当前沙盘的元数据取，换了沙盘就要重新取，不能留着上一块的。

### 5.5 `places.json`：回答落到哪栋楼

```jsonc
{
  "version": "v3",
  "boards":  { "学工": "ZQ-B023", "教务": "ZQ-B024", "后勤": "ZQ-B006", "保卫": "ZQ-B038", "图书馆": "ZQ-B034" },
  "issuers": { "教务处": "ZQ-B024", "石河子大学图书馆": "ZQ-B034", … },        // 出处的发布单位 → 楼号
  "names":   [ ["大学生活动中心", "ZQ-B023"], ["博学楼", "ZQ-B007"], ["护理学院", null], … ],   // 楼名、学院名 → 楼号；null 表示位置还没确认
  "packOf":  { "ZQ-B023": "all", "JJ-B019": "jjs", … }                        // 这栋楼不在眼前这块沙盘上时，换到哪一块去看它
}
```

**规则**（写成一个纯函数 `resolvePlace(response, places)`，返回楼号或 `null`）：

1. 只处理 `response.status === 'answer'` 的回答，别的状态返回 `null`。
2. 按顺序看 `response.answer.blocks` 的每一段 `text`。在一段文字里，找出 `names` 中所有出现过的名字，取**出现位置最靠前**的那个；位置相同取**更长**的那个。选中的名字对到一个楼号：就用它，不再往下看。对到 `null`，或者这一段里一个名字都没有：看下一段。
3. 所有段落都没有楼名：按顺序看 `response.citations`，第一个 `issuer` 在 `issuers` 里有的，就用它对应的楼。
4. 还没有：返回 `null`。

得到楼号后，看它在不在当前沙盘上（当前沙盘元数据的 `buildings` 里有没有这个楼号）。在，就进入 `answer` 状态。不在，就只在面板里显示一个钮：「这栋楼在「全校」沙盘上，点这里换过去」，去的是 `packOf[楼号]` 那一块；不自动切换。主校区的楼 `packOf` 一律是 `all`，将军山的楼是 `jjs`。

### 5.7 协助方保证的事（测试可以依赖）

下面的数字是协助方用自查工具在 1920×1080 的画面上量的。「偏红像素」指 R > 140、R − G > 50、R − B > 50 的像素；「饱和红色」「暗色」「暖色亮像素」的定义同 `NIGHT.md` 第 3.3 节。

1. `PLAN.md` 第 3.4 节对热点的保证（拾取点不被挡、标记点和拾取点分得开、海报对位）对七块沙盘的 `hotspots` 都成立。海报坐标 `posterDesktop` 是相对 2.4 比 1 的海报的。
2. 什么都没选中时，在 `home`、`overview` 上，动效的任何时刻、开场动画的任何时刻：饱和红色少于 0.05%，偏红像素少于 0.1%（七块沙盘的 `home` 实测最多 0.013% 和 0.022%，来自铭牌上那枚小印）。镜头贴近底座南边的铭牌时（靠南的几个停靠点和近景机位），那枚印占得多一些，实测最多 0.11% 和 0.16%；这不算选中了什么。
3. 七块沙盘的 `home` 机位：暗色像素多于 75%，暖色亮像素多于 0.15%。
4. 显示某个校区的 `Z_` 组，在它的停靠点上（片区没有 `stop` 的用 `overview`）：偏红像素多于 0.3%。
5. 显示 `meta.shells` 里任何一栋楼的 `H_` 组，在它的近景机位上：偏红像素多于 0.6%。
6. 把图钉放到一栋楼上，在它的近景机位上：偏红像素多于 0.25%（每块沙盘抽一栋没有外壳的楼实测）。
7. 每栋楼的近景机位（`focus`）在 16 比 9 的画面里：楼的 `anchor` 落在横向 25% 到 55%、纵向 30% 到 80% 之间。前面有高楼挡着的楼，机位已经换了方位，所以各楼近景的朝向不全一样，罗盘会如实转过去。
8. 动效滚动前后，全景画面里有变化的像素多于 0.2%（变化的定义同 `NIGHT.md` 第 3.3 节第 5 条；第 0 秒和第 3.1 秒两帧相比）。

### 6.2 `scene.ts` 新增的接口（形状照这个来，实现自己写）

```ts
type CameraPose = { position: [number, number, number]; target: [number, number, number] };

interface CampusSceneHandle {
  // ……原有的都保留……
  goTo(stop: string | CameraPose, opts?: { immediate?: boolean }): void;   // 现在也接受一个机位对象
  setShell(buildingId: string | null): void;   // 显示这栋楼的 H_ 组，同时隐藏上一个；null 只隐藏
  setZone(zoneId: string | null): void;        // 显示 Z_<zoneId>，同时隐藏上一个
  setPin(buildingId: string | null): void;     // 把 P_pin 挪到这栋楼并显示；null 隐藏
  getAzimuth(): number;                         // 镜头的方位角，0 到 360 度
  setOrbit(enabled: boolean): void;             // 允许用鼠标拖动旋转、滚轮缩放（W8）
  setTour(on: boolean): void;                   // 观景：绕当前目标点匀速转（W8）
}
```

**方位角**：从相机指向目标点的水平方向，相对正北顺时针的角度。场景坐标是 X 朝东、Y 朝上、Z 朝南，所以：`d = target − position`，方位角 `= atan2(d.x, −d.z)` 换成度，再规整到 0 到 360。朝正北看是 0，朝正东看是 90。

`setHighlight(board)`（按板块名高亮）保留给首页沙盘用，舞台上不用它。

## 10. 人工验收

把截图和一段 60 秒的录屏发给协助方，对照 `docs/3d/reference/stage/` 一起看。

**G6（W3 之后）骨架**
- 打开 `/stage`，海报到 3D 的切换不闪白、不跳位置。

## 11. 答辩时可能被问到的（作者本人要能讲清楚）

- **为什么做成 3D**：命题要求给出办理地点。别的方案是一行文字「某某楼几层」，我们直接飞到那栋楼。见第 2 节。
- **模型是怎么来的**：用 OpenStreetMap 的公开数据、卫星影像和学校公开资料复原，322 栋楼。在 Blender 里用脚本烘焙夜景光照。这一部分按赛事方的答复可以用其他工具完成。它是示意模型，不是测绘成果，页面上有说明。
- **六个校区都有吗**：都有，一共七块沙盘。全校一块，上面是主校区的五个校区；六个校区另外各有一块近看的。将军山校区离主校区约 7 公里，不在全校那一块上。将军山是按卫星图复原的第一版，没有实地核对，页面上写明了。
- **为什么要分七块**：全校一块有 303 栋楼，一眼能看出办事的楼在哪个校区；但楼太小，看不清是哪一栋。近看的沙盘范围小，同样大小的贴图分给更少的楼，所以更清楚。页面一次只加载一块。
- **哪些是参赛 agent 做的**：把模型接进页面的全部代码和测试，包括整屏舞台、校区切换、问答面板、回答落到楼上。每一步的记录在 `docs/3d/PROGRESS.md`。
- **回答落到楼上是怎么做的**：不靠大模型猜。回答文字里出现的楼名、出处的发布单位，查一张对照表（`places.json`）得到楼号。查不到就不动镜头，不乱指。
- **会不会拖慢回答**：不会。问答走的还是原来的接口，3D 只是在回答回来之后多做一次镜头移动。
- **没有显卡的电脑、手机怎么办**：进页面先判断设备，不适合的直接给普通版，功能一样。

## 12. 常见的坑

1. **换沙盘后旧的还在**：切换前没有调用旧场景的 `dispose()`，显存里留着两份。`geometries`、`textures` 会翻倍。
2. **全校的楼只有 5 栋能变红**：还在用 `setHighlight(board)`。舞台上用 `setShell(楼号)`；楼号不在 `meta.shells` 里的用 `setPin`。
3. **图钉立在沙盘正中间**：只改了缩放，没先设 `position`。
4. **图钉飘在半空**：`position.y` 用了楼的 `anchor.y`。要用 0。
5. **校区的红色界线一直亮着**：换校区、回首页时没有把上一个 `Z_` 组的缩放设回 0。
6. **罗盘转反了**：图要转的是 `−方位角`，不是 `+方位角`。
7. **题签不跟着镜头走**：位置只在状态变化时算了一次。要在 `onFrame` 回调里每帧重算。
8. **海报和 3D 对不上**：海报用了 `contain`，或者 3D 的视角跟着窗口变了。见第 4.1 节。
9. **普通版的页面也变黑了**：把颜色变量写进了 `:root`，或者选择器没有放在 `.stage` 之下。
10. **回答明明提到了楼名，镜头却不动**：`resolvePlace` 只看了第一段，或者只在 `kind` 等于某个值的段落里找。要按顺序看每一段。
11. **换到校区沙盘后，图钉、题签、引线都偏到别处去了**：还在用上一块沙盘的坐标或机位。同一栋楼在两块沙盘里坐标不同，见第 5.4 节最后一条。
12. **在校区沙盘里提问，楼就在眼前却让用户「换过去」**：用 `packOf` 判断了在不在当前沙盘。要看当前元数据的 `buildings`，见第 5.5 节。
13. **在舞台上提问后跳到了 `/chat`**：用了现有的 `useGo().ask()`，它会跳页。舞台上直接调 `useChatStore().send()`。
