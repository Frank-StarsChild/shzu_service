## 1. 改成什么样

现在的白模沙盘换成**夜景沙盘**：深色的校园、亮着暖色灯的窗、沿路的路灯光斑、冷色的建筑轮廓线，四周是淡出的城市街区。参考图在 `docs/3d/reference/`，文件名和画面的对应关系：

| 文件 | 画面 |
|---|---|
| `stop-overview.jpg` | 默认机位。3D 画出来应该和它一样，海报也是这一张 |
| `stop-xg.jpg` 等 5 张 | 镜头转到各板块时的画面（没有高亮） |
| `hl-xg.jpg` 等 5 张 | 同一机位，对应的楼高亮成红色 |
| `intro-0.0.jpg` … `intro-2.7.jpg` | 开场动画在第 0、0.5、1.0、1.5、2.1、2.7 秒的画面 |
| `fx-3.1s.jpg` | 动效运行 3.1 秒时的画面（光圈、流光的位置和 `stop-overview.jpg` 不同） |
| `ui-overview.jpg`、`ui-lib.jpg`、`ui-jw.jpg`、`ui-bw.jpg` | **带界面的目标效果**：画框、四角信息条、标记、板块按钮都在。N2 做完应该和它们一样 |
| `ui-mobile.jpg` | 手机宽度下的静态版 |
| `preview.mp4` | 14 秒的目标效果视频：开场动画 → 待机时的动效 → 悬停「图书馆」→ 回到全景 → 悬停「教务」。N5 做完应该和它一样 |

`ui-*.jpg` 和 `preview.mp4` 是协助方用同一个模型演出来的示意，里面的「79 条审定证据」「8 项服务」这类数字是示意值，页面上要显示接口返回的真实数字。

用户看到的过程：

1. 页面打开，黑色画框里是夜景海报。3D 准备好后淡入，播放 2.7 秒的开场：线框先立起来，楼从图书馆向外一栋栋长出来，最后五根光柱点亮，镜头同时从高处落到默认机位。
2. 之后画面一直是活的：光柱里有光向上流，热点楼脚下有光圈向外扩散，道路上有流光，每隔几秒有一圈扫描波扫过校园。
3. 鼠标移到板块按钮上：镜头转过去，那栋楼从底部涌起红色，红色光柱升起，标签展开，右下角显示楼名和这个板块有多少项服务。
4. 四角有等宽字体的信息条：校区名、经纬度、楼数、比例尺。
5. 手机、低配电脑、关掉 3D 的用户：看到夜景海报、同样的信息条和标记，功能不少。

## 2. 做法：外观都在资产包里，代码只做四件事

这次改版好看的部分**全部已经做进模型文件**。代码里不写着色器、不加灯、不调颜色、不新增任何依赖。要写的只有四件事：

| 事 | 做法 | 在哪张卡 |
|---|---|---|
| 换外观 | 换掉 `frontend/public/campus3d/` 里的四个文件 | N1 |
| 高亮一栋楼 | 把模型里名叫 `H_<楼号>` 的组的缩放从 0 改成 1 | N1 |
| 让画面动起来 | 每帧把一张贴图的横向偏移加一点 | N3 |
| 开场动画 | 播放模型自带的、名叫 `intro` 的动画片段 | N4 |

其余是页面上的文字和样式（N2）。

**模型的默认状态就是最终状态**：不播动画、不滚贴图，画面也是完整正确的。所以每张卡做完都是一个能用的版本，后面的卡做不成不影响前面的。

## 3. 资产包 v2 契约

文件名、位置、`B_` 和 `S_` 节点、`campus.meta.json` 里原有的字段，全部和 v1 相同。下面只写新增的。**资产包不许改。**

### 3.1 模型里新增的节点

| 节点名 | 是什么 | 代码要不要管 |
|---|---|---|
| `L_edges`、`L_hot`、`L_context` | 轮廓线（线段，不是网格） | 不用管 |
| `S_context` | 四周的街区 | 不用管 |
| `FX_beacons`、`FX_flow`、`FX_sweep` | 光柱和光圈、道路流光、扫描波。三者**共用同一张贴图** | N3：滚动这张贴图 |
| `H_<楼号>`，共 5 个 | 高亮件：一个组，里面有红色外壳、轮廓线、红色光柱和光圈。**文件里它的缩放是 `[0, 0, 0]`，所以默认看不见** | N1：缩放改成 1 就显示，改回 0 就隐藏 |

- 5 个 `H_` 组的名字是 `H_` 加热点的 `buildingId`，例如 `H_ZQ-B034`。它是组（`Object3D`），不是 Mesh。
- 高亮**不再克隆材质、不再改颜色**。夜景的贴图是深色的，乘上红色会发黑。
- 模型自带一个动画片段，名字在 `meta.look.intro.clip`（值是 `intro`），长 `meta.look.intro.seconds` 秒。它只改节点的缩放和位置，播完后所有节点回到默认状态。
- 射线拾取照旧只对 5 栋热点楼（`B_` 节点）做。`H_`、`FX_`、`L_` 都不参与拾取。

### 3.3 协助方保证的事（测试可以依赖）

1. `PLAN.md` 第 3.4 节的保证全部继续成立（拾取点不被挡、标记点位置、海报对位）。其中「与背景色有明显差别的像素不少于 30%」按新背景色 `#05080d` 计算。
2. 没有高亮时，任何机位、动效的任何时刻、开场动画的任何时刻，画面里都没有饱和红色（R > 170、G < 70、B < 70 的像素少于 0.05%）。
3. 某栋楼高亮后，在它自己的停靠点，饱和红色像素多于 0.3%。
4. `overview` 画面里，暗色像素（R + G + B < 150）多于 50%，暖色亮像素（R > 180、G > 110、B < 170、R − B > 40，也就是亮灯的窗）多于 0.1%。
5. 动效滚动 1 秒前后，`overview` 画面里有变化的像素（三个通道差的绝对值之和大于 40）多于 0.2%。
6. 开场动画第 0 秒，所有 `B_` 节点的 Y 缩放小于 0.01；播完后等于 1。
7. 预算不变：`campus.glb` 不超过 3 MB，绘制调用不超过 120，三角面不超过 30 万。

## 8. 答辩时可能被问到的（作者本人要能讲清楚）

- **模型是怎么来的**：用 OpenStreetMap 的公开数据和公开资料复原中区的楼，在 Blender 里用脚本烘焙夜景光照，导出成一个 2 MB 多的 glTF 文件。这一部分按赛事方的答复可以用其他工具完成。它是示意模型，不是测绘成果，页面上有署名和说明。
- **哪些是参赛 agent 做的**：把模型接进页面的全部代码和测试，包括加载、镜头、联动、回退、信息条、动效和开场动画的播放。每一步的记录在 `docs/3d/PROGRESS.md`。
- **为什么不卡**：光照是提前算好存进贴图的，浏览器里不算光、不算阴影；整个场景不到 80 次绘制调用；沙盘滚出屏幕或页面切到后台就停止渲染。
- **没有显卡的电脑怎么办**：进页面先判断设备，手机、软件渲染、省流量模式、用户关闭 3D 都给静态海报，功能一样不少；3D 加载失败也回到海报。
- **3D 和产品有什么关系**：五栋楼就是五个服务板块的入口，悬停时显示这个板块的服务数量（来自服务目录接口），点击进入对应的服务目录。它是导航，不是装饰。

## 9. 常见的坑

1. **换完资产后五栋楼全是红的**：把 `H_` 组的缩放改成了 1，或者用了 `visible`。默认什么都不用做，它就是隐藏的。
2. **高亮后楼发黑**：还在用旧的「克隆材质改颜色」。删掉，换成改 `H_` 组的缩放。
3. **用 `visible = true` 显示高亮件没反应**：它本来就是 `visible`，只是缩放为 0。要改的是 `scale`。
4. **动效不动**：改的不是 `FX_beacons` 那张贴图；或者改了 `offset` 但没有持续渲染。
5. **动效方向反了**（光往下流、光圈往里缩）：偏移量在减小。必须是随时间增大。
6. **开场动画播完楼缩回去了**：没有设置「播完停在最后一帧」（`clampWhenFinished`），或者循环方式不是只播一次。
7. **开场动画期间旧测试大面积超时或对不上位置**：旧测试都在等 `status === 'ready'`。开场期间 `status` 必须是 `intro`，播完才变成 `ready`。
8. **标记对位的旧测试变红**：把标签放进了标记按钮的正常文档流，按钮变宽了。标签要绝对定位，按钮本身保持 22×22。
9. **风扇一直转**：沙盘滚出视口后还在渲染。见 N3。
10. **颜色发灰或过曝**：和以前一样，`outputColorSpace = SRGBColorSpace`，`toneMapping = NoToneMapping`，不加灯。
