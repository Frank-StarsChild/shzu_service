请在当前「石大智多星」仓库里做一个对话驱动的办事流程图。

我想在比赛现场这样演示。学生在首页沙盘里直接问「我刚转专业，还能申请国家励志奖学金吗？要准备哪些材料？」右侧随回答出现办理路线。点开排名那一步，马上能看见哪些有学校文件支持，哪一项要问转入学院。学生在原输入框补充情况，右侧用新一轮的结果更新。换成问宿舍断网，右侧就出现自查和报修的分支。只有走到材料环节，才需要进入现有向导、预览文件和下载。

先看 git status，有正在修改的文件就基于当前内容接着做。按下面三步依次实现。先让固定的测试数据跑通，再用现有后端做真实验证。

一、给现有聊天接口加一个可选字段

先读 backend/app/contracts/models.py、backend/app/agent/graph.py、backend/app/api/v1.py 和 frontend/src/api/client.ts。给 ChatResponse 增加可选的 process，Python 和 TypeScript 字段名保持一致。使用现有 POST /api/v1/chat 和会话历史。把 process 放进实际保存的回复，保证同一 request_id 重放和刷新历史时能读到同一份路线。旧响应缺字段或字段为 null 都按原样显示。

process 第一版就是下面几个字段，先用这个结构把前后端对起来。

  title               办什么事
  nodes               按展示顺序排列的节点，3～6 个
  edges               节点之间的连接，形如 {from_id, to_id, label?}
  focus_id             首次展开哪个节点，可空
  workflow_entry       可空，形如 {node_id, flow_id, historical}，仅引用本轮已有向导

每个节点包含 id、title、detail、state、citation_ids。id 在同类流程里尽量稳定，例如 eligibility、materials。state 只用四种。

  ready               可查看，有依据的规则、步骤或已准备好的操作
  needs_user          待你补充，detail 写清楚缺的信息
  needs_check         待核实，detail 写清楚是年度公告、学院口径还是其他事项
  upcoming            后续步骤，例如还没开始的填表、预览或导出

「可查看」只表示有内容可看或者有动作可做。个人资格结论仍以已有的核对结果为准。focus_id 优先选择第一个需要学生补充的节点，其次选待核实节点，最后选首节点。节点 ID 要唯一，边只能从前面的节点指向后面已经定义的节点。任一事实节点的 citation_ids 必须能在同一回复的 citations 中找到。对于缺依据的节点，写明待核实的事项，或者只保留纯界面操作。

下面是一份只用来对接界面的模拟数据。evidence-1 和 evidence-2 要同时放进这次模拟答复的 citations，实际问答取后端返回的 ID。

二、在后端组装路线

在 graph.py 发布正常回复的位置接一个小的组装函数。生成路线用已有结果，不增加模型调用。最终验证失败就省略 process，保留正文、引用和原动作卡。不要改检索流程、表结构、模型供应商或全局超时。处理顺序如下。

1. 有适用的结构化动作时，优先用它。判断用本轮返回的卡种和字段，不按前端输入框里的关键词选图。

   奖助核对读已校验的 checklist。路线按「核实申报年度 → 核对资格 → 查看材料」组织。有适用向导才增加「生成并导出材料」。年度节点取真实年度和年度核对项，资格节点使用资格、认定、排名和兼得记录，材料节点用实际的材料核对项。给这些条目加稳定的可选 key，原 label 照常显示，graph.py 的 _validated_actions 校验后也要保留 key。转专业这一项如果出现在清单里，显示在资格节点里，保留「待学院确认」。同一节点既缺用户信息也缺学院口径时，状态用「待你补充」，展开内容同时显示两类缺项。已有依据的材料可以独立展开。

   先修正一个会影响这张图的口径问题。scenario_tools.py 里的 check_award_readiness 当前使用国家励志奖学金的依据包。只有明确匹配国家励志奖学金或它已有的别名时，才返回这张专用清单；遇到国家奖学金、国家助学金或未明确的奖项，交回现有检索或追问。不要用提问中单独出现的「排名」「认定」之类词，把个人条件标成已经核对。用户补充年级或身份时，复用现有用户自述与历史上下文，只更新真正补齐的条目。转专业的学院口径仍按来源状态显示。

   2025 年历史向导只给明确选择 2025 年或历史演示的人作为流程中的材料入口，并在按钮旁标明「2025 年历史演示」。当年通知或模板还没有入库时，材料留在「待核实」，往年内容明确标注年份，只作为参考。对话和图都不能把旧模板包装成当年适用材料。

   宿舍网络报修读 repair 卡。用「确认楼栋与影响范围 → 查看公告和自查 → 判断是否恢复」作为主线。判断后用两条有文字的分支连接「已恢复 → 结束自查」和「仍无法连接 → 查看官方报修入口」。公告和自查内容分别取已有 announcement 和 steps，报修入口取有出处的 entry。缺楼栋时标「待你补充」，公告未核实时沿用原来的实际结果。没有经引用确认的自查步骤或报修入口，就保留已有卡片与回答，不画这条分支。报修草稿继续通过现有按钮复制，保留「未提交」说明。

2. 状态为 workflow 时，用 kb.flows 中已经通过适用性检查的 steps。正面验收用教学场所临时借用。节点顺序、名称和说明取实际定义，已登记的步骤证据通过现有引用解析加入本轮 citations，然后再填 citation_ids。材料节点复用本轮已有 workflow 或 checklist.flow 引用。教学场所借用把入口挂在 print，已有 document 节点的向导挂在 document。教学场所借用向导提供的是办事材料与指引，教务系统申请和审核照现有官方流程办理。现有向导预设、确认、校验和预览 token 都照常使用。向导中的填表、申请和导出环节默认显示「后续步骤」。

3. 其他事项用一个窄的通用入口。在现有模型最终 JSON 里允许给 answer 额外带 process_candidate，格式为 {title, steps: [{title, detail, evidence_ids}]}。只有用户在问办理方式、有至少 3 个明确且有实际先后关系的步骤，而且每一步都能引用直接支持它的本轮官方条款时，才填这个字段。模型仅提议步骤和出处，后端检查后按数组顺序生成节点和边，不接受模型自填 flow_id、链接或执行动作。只要求线性流程。把候选字段从核心 ModelDecision 分开解析，候选坏了不能让本来正常的答复变成 500 或技术错误。任一步缺直接依据、只有官网标题线索、引用不在本轮工具证据中或无法解析，就放弃整张候选图。与现有引用上限协同，别在图上产生点不开的出处。引用 ID 的校验只能证明出处存在，手工验收还要打开原文核对步骤内容。

clarify 继续显示现有问题和选项，接受自由补充。insufficient 只在有现成场景卡且仍有可展示的具体环节时允许出图，缺项明确标出来。普通事实答复、闲聊、超范围、技术错误都沿用现有回答。换话题用最新响应，不把上轮路线拼接到新问题里。

三、接到首页右侧，再验收

新增一个共享的 ProcessPanel.vue，接收 process 和本轮 citations。首页放到 components/stage/AnswerPanel.vue 已有的右侧滚动区，流程优先在摘要附近出现，正文和引用仍可继续查看。普通 /chat 把同一个组件放在它所属的助手消息中，右侧证据栏继续负责显示原文。线性流程用纵向节点和连线，分支用带条件文字的两条子路线，手机也保持纵向。用现有样式变量和简单 CSS。节点可键盘展开，状态要有文字。默认展开 focus_id，其余节点可逐个点开。切换 request_id 后，以新一轮为准重新展开节点。

点节点里的出处，首页调用 AnswerPanel 已有的 onCite，普通聊天调用 ChatView 已有的 onCite(t, id)。确保 workflow 状态也有实际可以展开的出处区域。材料节点用它的 workflow_entry 匹配同一回复里的 workflow 或 checklist.flow，从原引用取 preset_slots 和 preset_note，沿用原 /workflows/:flowId 跳转。匹配不到就只显示步骤。相同的向导按钮留一个，旧消息没有图时照常显示原按钮。继续补充使用已有输入框和 pickChoice。不要加流程编辑器、任务数据库、自动提交或新的导出接口。

交付时至少验证下面这些。后端用可控输入测组装和无效候选。前端复用 frontend/tests/e2e/fixtures/api.ts 测一条右侧真实渲染链路，模拟数据和真实问答分开记录。

1. 问当前申报年度的励志奖学金和转专业排名。打开对应节点，检查年度、学院口径、材料三件事各自显示正确。如果库里仍缺当年通知，不能显示当年模板可用。再补一句「我是大二本科生」，只更新确实补齐的身份信息，学院待确认项仍在。另问「国家奖学金怎么申请」，不能出现励志奖学金专用条件或专用图。
2. 明确问「按 2025 年国家励志奖学金做历史演示」。能从材料节点进入实际向导，填演示数据，按原校验预览并下载一份可打开的 Word 文件，且下载前的历史演示说明仍存在。
3. 同一会话换问「中区 18 号楼宿舍网断了，怎么自查和报修」，右侧换成带条件分支的网络路线。再问教学场所临时借用，能看到已有向导定义里的步骤。用一组本轮真实条款构造通用候选，检查可以证实的路线会显示，加入一个假引用后正文仍正常且没有图。
4. 用一条普通事实问答、一次需要澄清的问答、一份缺 process 的旧响应确认原功能。检查 1440px 和 390px：能读全节点，点出处会展开本轮正确的原文，输入和取消仍可用。刷新后回看有流程的消息，图和原引用仍对应。

从 frontend 运行 npm run build 和 npm run test:unit，再跑本次相关的 Playwright 用例。最后写清楚改了哪些文件，哪些是模拟验收，哪些是真实后端问答或实际下载。记录可测到的单轮接口耗时，有超 5 秒的样本照实列出。真实模型不可用时，明确标出相应的未验收项。
